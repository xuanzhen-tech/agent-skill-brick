# ASIN 深度研究编排运行手册

## 问题与责任

| 用户问题 | 责任模块 | 最细合格上游原料 | 结论上限 |
|---|---|---|---|
| 对象是谁、当前位置如何 | 竞争格局 | 身份、类目、当前字段 | 供应商可见样本 |
| 价格、订单估算、BSR、评分怎样变化 | 事件趋势 | 实际最细合格的时间序列或快照区间 | 描述性变化/候选机制 |
| Listing 改了什么 | Listing | 完整当前字段、可比历史快照或重复本地快照 | 可见快照差异与变更区间 |
| 买家关注什么 | VOC | 逐条评论、可审计分页、站点日期或其他已验证时间语义 | 返回语料内 VOC |
| 外部广告/流量信号如何 | 广告可见性 | 通道、词、时间字段 | 外部可见信号 |
| 店铺是否出现新品 | 竞争格局 | 稳定店铺实体、商品集合、日期和分页 | 当前可见集合或本地首次发现 |
| 为什么变化、能否借鉴 | 总控 | 经审查的跨模块结果与用户第一方事件 | 不越过证据等级 |

## 0. 能力与覆盖预检：先验证，再调度

在专家线程启动前，总控为每个关键业务问题运行 `search → describe → call`。`call` 不只是取数：必须用小样本确认字段实际返回、对象层级、日期语义、分页和参数行为。将结果写入内部能力与覆盖登记，至少包括：

```yaml
metric_or_question: required
candidate_endpoints: required
validated_endpoint_and_fields: required
sample_object_scope: child_asin | parent_asin | variation_pool | category | unknown
requested_parameters: required
parameter_behavior: verified_effective | ignored_or_unverified | partially_effective
actual_time_grain: record | day | week | month | snapshot_interval | current | unknown
actual_period_and_timezone: required
unit_and_field_semantics: required
coverage_and_breaks: required
allowed_local_processing: required
nearest_related_evidence: required
analysis_route: required
```

### 参数行为验证

- 对时间、分页、对象、排序、字段投影或聚合参数，发送两个预期结果显著不同的受控请求。
- 比对返回记录、日期、页码、字段或对象范围。schema 接受而响应不变，视为参数未证明有效。
- 参数未验证有效时，改用宽范围/全分页采集后本地筛选、拆段请求、不同端点或重复快照；不要以该参数为唯一范围依据。
- 避免因 MCP 的静默忽略、默认页大小、截断或缓存行为提前终止研究。

### 粒度选择

- 首先追求逐条记录、子 ASIN、日级等最细粒度。
- 以实际稳定返回、语义可核验且适合问题的最细粒度作为报告粒度；日级不是绝对门禁。
- 非日级结果必须保留其真实月度、周度、快照区间或当前快照属性；禁止无依据切分、日均摊、插值或伪造成日级。

## 执行依赖

1. 冻结 case、marketplace、ASIN、父子体、变体、店铺范围、时间、站点时区、币种和问题。
2. 完成广覆盖的能力与覆盖预检：先对 MCP 工具目录做宽范围搜索，再对所有与研究问题及其竞争、趋势、价格/促销、销量/需求、Listing/媒体、评论、店铺/类目、关键词/可见性和事件解释直接或合理关联的候选能力执行 `search → describe → call`。确认原料、参数行为、真实粒度、对象范围、覆盖、可用本地加工和关联路由；不设工具种类或端点种类上限，也不因首个端点返回部分数据而停止。仅当新增能力与当前问题无关、重复，或预期不能改变结论、反证、替代解释或行动建议时，才可不继续扩展。
3. 建立对象登记和 dataset version；未通过身份门的对象不进入直接横向比较。
4. 在共享口径稳定后并行启动竞争格局与事件趋势；Listing、VOC、广告在获得相应原料和明确本地处理规则后启动。
5. 专家只消费已授权的只读数据。补数请求必须说明支持或推翻哪个问题、固定部分、事件或因素链。
6. 先验收 Module Result 结构和能力信息，再审查数值、图表、主张、事件链、替代解释和限制。
7. 更新 dataset version 后只重算受影响模块；旧结果标为 superseded，不混入最终图表。
8. 七个固定部分均取得可审查输入后才合成 HTML。直接字段不足时继续搜索关联原料并组织可支持的邻近结论；不要只因预设字段为空而收尾。

## 专家结果到七部分的映射

| 固定部分 | 首选直接结果 | 实际能力不足时的同章节路由 |
|---|---|---|
| 01 报告概览 | 当前快照、Listing 当前字段、事件最新值、VOC 摘要 | 展示对象/粒度/覆盖摘要，并以已审查的竞争定位、关键事件与因素链形成结论 |
| 02 价格趋势图 | 最细合格价格、Deal/Buy Box/List/Coupon 序列 | 当前快照或历史快照仅作锚点；将价格事件与促销、Listing、BSR、评论、可见性证据对齐，不伪造未返回价格线 |
| 03 订单趋势图 | 同对象的日级供应商销量/订单估算 | 使用最细可用的周/月销量估算；若没有销量数值，组织与需求/销量直接关联的 BSR、价格、评论发表量、可见性和竞争事件信号，并清楚标识不是订单数 |
| 04 BSR 排名趋势图 | 最细合格 BSR 序列及其实际类目字段 | 无逐日类目层级时，仅画历史 BSR 数值轨迹；将当前大/小类目排名作为采集时点快照，不回填历史层级 |
| 05 评分趋势图 | 星级、累计评分数和可复算相邻差分 | 记录字段断点、倒退或刷新；以逐条评论或当前快照补充解释，不把修订当真实负面事件 |
| 06 评论分析 | 本地筛选、去重后的逐条评论、主题、星级、趋势和匿名证据 | 服务端窗口参数失效但 `date` 语义有效时，全页采集后本地筛选；分页/对象范围只能支持样本时，降级为样本观察而不伪造总体比例 |
| 07 变动监控 | 可观察事件、Listing/价格/评论/排名变化和跨模块因素 | 对每个材料性结果信号搜索动作/事件、直接因素、间接因素、替代解释及验证动作；评论比例代理仅在分子/分母同口径时计算 |

广告/流量可见性与店铺新品只在材料性足够时作为概览证据、既有图表事件或对应部分的补充卡片，不能创建第八部分。

## 因素搜索与事件归因

总控对每个材料性异常、拐点、差异或稳定期执行以下搜索，而不是仅计算指标：

1. 锁定结果信号：对象、实际粒度、前后窗口、幅度、数据质量和证据 ID。
2. 在同一对象与时间附近检索可观察动作：价格/促销、标题/Bullet、变体、图片/视频/A+、类目、可见性、评论主题与数量。
3. 在竞争对象与市场环境中检索直接关联信号：竞争价格带、产品形态/容量、排名、关键词/推荐标签、同窗口可见变化。
4. 形成因素图：
   - `directFactors` 是可观察且可对齐的事实；
   - `indirectFactors` 是具有业务逻辑与证据支撑的候选机制；
   - `alternativeExplanations` 是尚未排除的同等解释；
   - `validationPlan` 是可推翻或区分解释的第一方数据、后续快照、指标和观察窗。
5. 不将因素图转换成未经验证的因果或百分比权重。没有独立模型/数据时，用证据支持度表达相对强弱。

## 第一轮专家验收

### 全模块共同验收

- 是否引用能力预检：实际端点/字段、参数行为、对象范围、粒度、单位、期间与本地加工规则？
- 是否在直接字段不足时搜索并返回最邻近的关联证据，而不是只报空值？
- 是否将观察、加工/计算、代理/信号、解释/假设分层？

### 竞争格局

- 用户指定对象是否全部登记，身份和可比性依据是什么？
- 当前快照字段来自哪里，哪些字段可作当前锚点而非历史序列？
- 店铺实体、分页和日期是否真的足以形成新品证据？

### 事件趋势

- 价格、销量估算、BSR 和评分各自实际可得的最细粒度、真实覆盖和对象范围是什么？
- 哪些参数经行为验证有效；哪些端点/字段虽在 schema 中但对本对象未形成原料？
- BSR 历史序列是否真的带类目/node 层级；若没有，是否将当前类目快照与历史数值分开？
- 是否把月级销量、父体值、未结束期或未知价格语义错误伪装成日级、子体或真实订单？
- 事件是否已寻找价格、Listing、VOC、竞争及可见性等关联因素和替代解释？

### Listing

- 当前字段、历史快照和精确修改日志是否被分开描述？
- 前后版本是否可比；发现时间是否错误写成实际修改时间？
- 不同数据源的 title/image URL 差异是否先按字段来源差异处理，而非直接判作页面变更？

### VOC

- `review.date` 的日期/时区语义和分页参数是否经过验证？服务端时间过滤若无效，是否全页采集后本地按已验证日期筛选？
- 分页、对象（子体/父体/变体池）、去重和 codebook 是否足以支持主题比例与趋势？
- 是否将主题、情感、摘要和趋势明确为本地分析派生？
- 评论比例代理是否同时满足同对象、同站点、同期间、同粒度和单位明确的销量估算分母？若不满足，是否转为评论发表量/主题趋势等邻近结果？

### 广告可见性

- 自然、Ads 标签和推荐信号是否保持分离？
- 是否作为因素搜索的外部可见信号，而非实际账户表现或因果证据？

## 补数和停止

补数必须指向具体问题、固定部分、事件或因素链；实际能力有可能返回不同证据；新结果既可能支持也可能推翻当前解释；范围有界。除补数外，若当前结论主要来自单一端点、单一字段或单一模块，必须继续检索可提供独立观察、反证或替代解释的相关 MCP 能力；不以工具调用种类数量为上限。参数失效、截断、空字段或粒度不匹配时，应优先尝试受控重试、替代端点、分页/分段、本地处理、重复快照和关联原料。

当继续查询不再实质改变结论、替代解释、行动建议或验证路径，或实际能力无法取得所需原料时才停止该分支。停止不等于空白：用已验证事实、关联信号、不能跨越的边界和最小验证行动完成对应固定部分。

## 最终合成

1. 锁定 final dataset version、能力预检和参数行为结论，合并去重 claims，并保留无法裁决的冲突。
2. 验收七个固定部分均采用了最细合格原料及可审查的关联路由。
3. 复制 `assets/report-template.html` 为 `outputs/amazon-asin-research/<case_id>/report.html`，只编辑副本。
4. 按模板注释将真实数据、实际粒度、状态、事件链和分析填入 `REPORT_DATA`，只在明确扩展点增加同类对象或记录。
5. 先构建图表、预警、匿名证据和交互事件，再为价格、订单、BSR、评分、评论逐段写读图、事件/因素解释、证据、替代解释、限制和可逆验证计划。
6. 将材料性拐点写入 `REPORT_DATA.events`。总控必须综合数值、Listing、VOC、竞争格局和可见性证据填入 `directFactors`、`indirectFactors`、`impact`、同口径 `comparison`、`recommendations`、`alternativeExplanations` 与验证条件；不要把相关性升级为因果。
7. 将评论比例代理（若具资格）、异常筛查、L1/L2/L3、数据溯源、建议和观察/预测时间线写入 `REPORT_DATA.deepDiagnostics`。不具资格时展示可见评论量、主题趋势、关联事件或验证路径，不伪造代理。
8. 将 `templateMode` 改为 `false`，检查无预览数据、无外部脚本依赖、无越界结论。
9. 只向用户发布 `report.html`。
