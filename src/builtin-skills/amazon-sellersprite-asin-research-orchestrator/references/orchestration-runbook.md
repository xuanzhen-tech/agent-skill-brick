# ASIN 深度研究编排运行手册

## 1. 问题—模块—产物映射

| 用户问题 | 主模块 | 必需上游 | 核心产物 | 结构性上限 |
|---|---|---|---|---|
| 谁是真正竞品、位置如何 | 市场 | 身份/类目/当前画像 | competitor-role, landscape | 样本市场代理 |
| 最近为何变化 | 事件 | 可比时间序列 | event ledger, hypotheses | 候选驱动非因果 |
| Listing差在哪里 | Listing | 完整字段/版本 | field audit, diff, hypotheses | 不含未返回页面 |
| 竞品广告打法/词缺口 | 广告可见性 | 词/排名/通道 | channel matrix, validation queue | 非账户真相 |
| 买家痛点/评论异常 | VOC | 逐评正文/覆盖 | codebook, theme, anomaly matrix | 不认定刷评 |
| 能否复刻 | 总控+条件专家 | 上述主张+自有事实 | validation plan | 不直接执行 |

## 2. 第一轮任务卡的验收问题

### 市场专家
1. 每个用户指定竞品的角色是什么，逐维证据是什么？
2. 市场边界、类目节点和样本覆盖是什么？
3. 自有 ASIN 在价格/评价/生命周期/词结构的位置是什么？
4. 哪些市场背景可能反驳“竞品个体打法”解释？

### 数据专家
1. 哪些序列 fully comparable，哪些存在断点？
2. 哪些变化可复算，拐点/事件窗口是否合格？
3. 哪些候选机制满足时间和范围匹配？
4. 主要混杂和下一反证是什么？

### Listing专家
1. 每个字段的 readiness 状态是什么？
2. 竞品如何组织事实、利益、证据和条件？
3. 哪些差异是可证明版本差异？
4. 哪些机制可迁移，需哪些自有产品事实？

### 广告专家
1. 自然/广告/推荐三通道覆盖是什么？
2. 词簇和ASIN覆盖缺口是什么，分母是什么？
3. 可见机制假设和替代解释是什么？
4. 哪些一方报表字段能验证？

### VOC专家
1. 语料和分页覆盖是否合格？
2. 核心好评/差评/场景主题及样本分母是什么？
3. 哪些异常信号通过双信号门？
4. 正常替代解释与风险handoff是什么？

## 3. P0/P1主张优先级

- `P0`：会改变是否继续验证、是否进入执行前评审或重大风险认知；
- `P1`：会改变具体测试模块、词簇、内容或促销方向；
- `P2`：背景解释；
- `P3`：附录事实。

只有 P0/P1 触发补数和强制反证；P2/P3 不得无限延长研究。

## 4. 补数决策

批准补数需同时满足：
- 精确指向一个 claim/question；
- SellerSprite 候选能力实际可能返回所需字段；
- 新结果存在支持和推翻两种可能，而不是只为装饰；
- 查询范围有界；
- 已说明不补数的降级结论。

## 5. 最终合成顺序

1. 锁定 final dataset version；
2. 汇总所有 claim card，去除重复主张；
3. 处理冲突、结构性上限和专家状态；
4. 按 P0/P1 选执行摘要；
5. 建“竞品机制—自有条件—验证动作”映射；
6. 回链证据和模块产物；
7. 运行总控质量门；
8. 只发布 outputs 正式文件。
