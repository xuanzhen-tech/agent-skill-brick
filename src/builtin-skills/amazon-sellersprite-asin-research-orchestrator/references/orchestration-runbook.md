# ASIN 深度研究编排运行手册

## 问题、责任与视觉结果

| 用户问题 | 责任模块 | 必需上游 | 主要视觉结果 | 结论上限 |
|---|---|---|---|---|
| 对象是谁、当前位置如何 | 竞争格局 | 身份、类目、当前字段 | 当前比较快照 | 供应商可见样本 |
| 价格、销量估算、BSR、评价怎样变化 | 事件趋势 | 可比时间序列 | 四类趋势和事件标记 | 描述性变化/候选机制 |
| Listing 改了什么 | Listing | 完整当前字段、可比旧快照 | 文本和图片前后差异 | 可见快照差异 |
| 买家关注什么 | VOC | 合格逐条评论、分页覆盖 | 主题树表和主题趋势 | 返回语料内 VOC |
| 外部广告/流量信号如何 | 广告可见性 | 通道、词、时间字段 | 可见性矩阵或时间线 | 外部可见信号 |
| 店铺是否出现新品 | 竞争格局 | 稳定店铺实体、商品集合、日期和分页 | 新品时间线/窗口统计 | 当前可见集合或本地首次发现 |
| 为什么变化、能否借鉴 | 总控 | 上述经审查结果、自有事实 | 时间线、候选机制、验证计划 | 不越过证据等级 |

## 执行依赖

1. 冻结 case、marketplace、ASIN、父子体、变体、店铺范围、时间、粒度、币种和问题。
2. 运行能力探测，确认 SellerSprite 实际可用字段、分页、历史、图片和时间语义。
3. 建立对象登记和 dataset version；未通过身份门的对象不进入比较。
4. 在共享口径稳定后并行启动竞争格局与事件趋势；Listing、VOC、广告模块分别在字段、语料和通道 readiness 通过后启动。
5. 专家只消费已授权的只读数据。补数请求必须说明支持或推翻哪个问题、视觉需求或 claim。
6. 先验收 Module Result 结构，再审查数字、图表、主张、替代解释和限制。
7. 更新 dataset version 后只重算受影响模块；旧结果标为 superseded，不混入最终图表。
8. 十一类核心视觉需求全部取得状态后再合成 HTML；关键问题未回答时继续补证或明确阻断。

## 第一轮专家验收问题

### 竞争格局

- 用户指定对象是否全部登记，身份和可比性依据是什么？
- 当前快照字段来自哪里，哪些是缺失而非零？
- 店铺实体、分页和日期是否足以支持新品观测？
- 市场背景是否能反驳对单个竞品动作的解释？

### 事件趋势

- 哪些序列 fully comparable，哪些存在对象、类目、粒度或定义断点？
- 价格、销量估算、BSR、星级和评论序列是否分别保留语义？
- 事件标记和候选 t0 的来源是什么？
- 负评论增量、未结束期、缺失和异常值如何处理？

### Listing

- 当前字段和媒体处于什么 readiness？
- 历史来自供应商序列还是本地重复快照？
- 前后版本是否真的可比，发现时间能否等同修改时间？
- 图片是内嵌、远程引用、仅元数据还是不可用？

### VOC

- 评论正文、分页、时间、对象和去重是否合格？
- 主题表与主题趋势的分子、分母和 codebook 是否稳定？
- ASIN、父体和类目语料是否真正可比？
- 异常信号有哪些正常替代解释？

### 广告可见性

- 自然、Ads 标记和推荐信号是否保持分离？
- 时间字段和实体字段能否支持时间线？
- 气泡大小是否绑定真实字段；无合格指标时是否改用等大点？
- 哪些第一方字段才能验证实际广告表现？

## 补数和停止

补数必须同时满足：精确指向问题/视觉/claim、实际能力可能返回所需数据、新结果既可能支持也可能推翻当前判断、范围有界、已说明不补数的降级结果。P0/P1 通常优先触发补数；P2/P3 的材料性事实仍可进入报告，但不得无限延长研究。

当继续查询不再实质改变结论、限制或下一步，或者实际能力无法取得所需数据时停止相应分支。停止不是填空：核心视觉需求保留状态卡，说明已验证事实、阻断原因、不可推断内容和最小恢复条件。

## 最终合成

1. 锁定 final dataset version。
2. 合并去重 claims，记录无法裁决的冲突。
3. 验收十一类核心视觉需求状态。
4. 先构建图表与快照，再写读图、解释和限制。
5. 按证据材料性选择执行摘要和建议，不限制数量。
6. 将竞品观察连接到自有事实门、可逆验证和停止条件。
7. 使用 HTML 合同和模板，检查无模拟数据、无外部证据依赖、无越界结论。
8. 只发布 `report.html`。
