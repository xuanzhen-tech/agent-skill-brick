# ASIN 深度研究编排运行手册

## 问题与责任

| 用户问题 | 责任模块 | 必需上游 | 结论上限 |
|---|---|---|---|
| 对象是谁、当前位置如何 | 竞争格局 | 身份、类目、当前字段 | 供应商可见样本 |
| 价格、订单估算、BSR、评分怎样变化 | 事件趋势 | 可比日级时间序列 | 描述性变化/候选机制 |
| Listing 改了什么 | Listing | 完整当前字段、可比旧快照 | 可见快照差异 |
| 买家关注什么 | VOC | 合格逐条评论、分页覆盖 | 返回语料内 VOC |
| 外部广告/流量信号如何 | 广告可见性 | 通道、词、时间字段 | 外部可见信号 |
| 店铺是否出现新品 | 竞争格局 | 稳定店铺实体、商品集合、日期和分页 | 当前可见集合或本地首次发现 |
| 为什么变化、能否借鉴 | 总控 | 上述经审查结果、自有事实 | 不越过证据等级 |

## 执行依赖

1. 冻结 case、marketplace、ASIN、父子体、变体、店铺范围、时间、粒度、币种和问题。
2. 运行能力探测，确认 SellerSprite 实际可用字段、分页、半年历史、图片和时间语义。
3. 建立对象登记和 dataset version；未通过身份门的对象不进入比较。
4. 在共享口径稳定后并行启动竞争格局与事件趋势；Listing、VOC、广告分别在字段、语料和通道就绪后启动。
5. 专家只消费已授权的只读数据。补数请求必须说明支持或推翻哪个问题、报告部分或 claim。
6. 先验收 Module Result 结构，再审查数字、图表、主张、替代解释和限制。
7. 更新 dataset version 后只重算受影响模块；旧结果标为 superseded，不混入最终图表。
8. 七个固定部分全部取得输入状态后再合成 HTML；未回答的问题继续补证或明确阻断。

## 专家结果到七部分的映射

| 固定部分 | 必需结果 | 组装规则 |
|---|---|---|
| 01 报告概览 | 竞争格局当前快照；Listing 当前字段；事件最新值；VOC 摘要 | 总控去重并形成综合结论；按材料性生成零到多条预警，每条绑定证据 |
| 02 价格趋势图 | 事件价格序列与促销标记 | 最近半年、日粒度；只绘制 MCP 实际支持且返回的价格类型；选区对比显示在图内；图后必须给出分析、证据和限制 |
| 03 订单趋势图 | 事件销量/订单估算序列 | 最近半年、日粒度；标题、图例与 Tooltip 均标明供应商估算；选区对比显示在图内，图后解释变化 |
| 04 BSR 排名趋势图 | 事件大类目和小类目序列 | 最近半年、日粒度；排名越小越好；小类目动态增减；选区对比显示在图内，图后说明竞争格局变化和替代解释 |
| 05 评分趋势图 | 事件星级和累计评分数 | 最近半年、日粒度；新增评分数只由相邻日累计值差分派生；选区对比显示在图内，图后解释修订或异常点 |
| 06 评论分析 | VOC 主题明细、可比较趋势和匿名证据ID | 逐条评论是直接证据；主题、方向、比例、摘要和趋势均为分析派生；图后给出样本限制 |
| 07 变动监控 | VOC 评论比例代理/异常筛查；Listing 和数值事件；跨模块证据 | 用交互事件图的 Tooltip 展示变动前后；再组织 L1/L2/L3、溯源可信度、建议和观察/预测时间线 |

广告/流量可见性与店铺新品只在材料性足够时作为概览证据、图表事件或对应部分的补充卡片，不能创建第八部分或替代七部分中的缺失数据。

## 第一轮专家验收

### 竞争格局

- 用户指定对象是否全部登记，身份和可比性依据是什么？
- 当前快照字段来自哪里，哪些是缺失而非零？
- `REPORT_DATA.products` 所需字段是否都有真实状态？
- 店铺实体、分页和日期是否真的足以形成可选新品证据？

### 事件趋势

- 价格、订单估算、BSR 和评分是否查询最近半年日级序列，真实覆盖从哪天到哪天？
- 哪些价格类型由实际 MCP 支持并返回，哪些整条系列应删除？
- BSR 返回了哪些真实类目，小类目数量是否动态而非固定？
- 星级和累计评分数是否直返，新增评分数是否仅由相邻日累计值差分？
- 缺失、未结束期、负增量、断点和异常值如何处理？

### Listing

- 当前字段和媒体处于什么 readiness？
- 历史来自供应商序列还是本地重复快照？
- 前后版本是否真的可比，发现时间能否等同修改时间？
- 媒体是否使用主图、尺寸图、场景图等语义槽位，并保留真实能力状态？

### VOC

- 评论正文、分页、时间、对象和去重是否合格？
- 每个主题比例的命中数、合格分母和 codebook 是否稳定？
- ASIN、父体和类目样本是否各自说明覆盖，能否真正比较？
- 主题、情感、摘要和趋势是否明确为分析派生，而非 MCP 直返字段？
- 是否返回匿名评论 evidence ID、日期、星级和最小充分摘录，而未包含评论者身份画像？
- 评论比例代理是否使用同对象同期间的分子/供应商估算分母，并明确不是真实留评率？异常筛查是否保留替代解释且不判定人为干预？

### 广告可见性

- 自然、Ads 标记和推荐信号是否保持分离？
- 结果是否足够材料性，只应进入概览或既有图表事件？
- 是否避免创建独立报告章节或用广告结果填补其他部分？
- 哪些第一方字段才能验证实际广告表现？

## 补数和停止

补数必须同时满足：精确指向问题/固定部分/claim、实际能力可能返回所需数据、新结果既可能支持也可能推翻当前判断、范围有界、已说明不补数的降级结果。当继续查询不再实质改变结论、限制或下一步，或者实际能力无法取得所需数据时停止相应分支。

停止不是填空：对应固定部分保留状态卡，说明已验证事实、阻断原因、不可推断内容和最小恢复条件。

## 最终合成

1. 锁定 final dataset version，合并去重 claims，并保留无法裁决的冲突。
2. 验收七个固定部分的输入状态与映射。
3. 复制 `assets/report-template.html` 为 `outputs/amazon-asin-research/<case_id>/report.html`，只编辑副本。
4. 按模板注释将真实数据、状态和分析填入 `REPORT_DATA`，只在明确扩展点增加同类对象或记录。
5. 先构建图表、预警、匿名证据和交互事件，再为价格、订单、BSR、评分、评论逐段写读图、解释、证据、限制和可逆验证计划。
6. 将标题、Bullet、图片 URL、价格、订单估算、评论、评分和排名的材料性拐点写入 `REPORT_DATA.events`。总控必须把数值、Listing、VOC、竞争格局和可见性证据综合为 `directFactors`、`indirectFactors`、`impact`、同口径 `comparison`、`recommendations` 和 `alternativeExplanations`，只通过主图标记或第 7 部分事件图富 Tooltip 展示；不要恢复独立 diff 表，也不要把相关性升级为因果。
7. 将评论比例代理、异常筛查、L1/L2/L3、数据溯源、建议和观察/预测时间线写入 `REPORT_DATA.deepDiagnostics`，缺证据的子项显示真实状态或删除可选记录。
8. 将 `templateMode` 改为 `false`，检查无预览数据、无外部脚本依赖、无越界结论。
9. 只向用户发布 `report.html`。
