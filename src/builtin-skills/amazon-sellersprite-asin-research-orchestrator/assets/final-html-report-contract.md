# 最终 HTML 报告合同

## 固定结构：不得改变

最终文件必须是基于 `assets/report-template.html` 副本编辑的单一 UTF-8 HTML：

`outputs/amazon-asin-research/<case_id>/report.html`

以下七个一级部分的顺序、锚点、DOM id、导航和对应渲染入口固定，不能删除、改名、换序或增加平级章节：

1. `overview` — 01 报告概览
2. `price` — 02 价格趋势图
3. `orders` — 03 订单趋势图
4. `bsr` — 04 BSR 排名趋势图
5. `rating` — 05 评分趋势图
6. `reviews` — 06 评论分析
7. `changes` — 07 变动监控

固定部分承载固定业务问题，而非强制固定的字段、端点、日级粒度或单一图表。正式报告仍只替换模板副本中的 `REPORT_DATA`，并只在模板明确扩展点内增减同类对象或记录。

## 数据能力、粒度与本地加工

- 总控必须先完成 `search → describe → call` 的广覆盖能力与覆盖预检：先宽范围搜索 MCP 工具目录，再验证所有与研究问题及其竞争、趋势、价格/促销、销量/需求、Listing/媒体、评论、店铺/类目、关键词/可见性和事件解释直接或合理关联的候选能力；不设 MCP 工具种类、端点种类或调用种类上限，不因首个端点返回部分数据而停止探索。候选能力须按其对结论、交叉验证、反证、替代解释或行动建议的预期信息增益纳入；不为凑数量调用无关、重复且不能改变判断的能力。并验证会影响对象、期间、分页、排序和字段的参数行为。Schema 接受参数不等于参数已经执行。
- 每一部分优先展示 MCP 实际稳定返回、语义可核验、对象可追溯的最细合格粒度：逐条记录优先于汇总，子 ASIN 优先于父体，日级优先于周/月/快照，但日级不是绝对门槛。
- 实际非日级数据必须用其真实周、月、快照区间或当前快照粒度展示，标出对象、期间、单位、数据性质和限制；不得按日均摊、插值、复制或以当前值填补历史。
- MCP 原始响应可经本地可复算处理后进入报告，包括筛选、清洗、去重、标准化、聚合、差分、主题编码、快照比较和时间对齐。报告必须将直接观察、本地加工/计算、估算/代理、解释/假设区分清楚。
- 当直接字段不足时，不应只呈现空图。应在对应固定部分展示最邻近的关联信号、可观察事件、证据支持的候选机制和验证路径；不能把这些信号伪装为原问题的直接数值或因果事实。

## 各固定部分的呈现合同

| 部分 | 直接证据优先级 | 非日级/直接字段不足时的允许呈现 |
|---|---|---|
| 01 概览 | 当前对象、类目、价格、排名、Listing、评分与评论快照 | 展示实际粒度/对象/覆盖摘要和本次最材料性结论；不把能力预检做成冗长空状态表 |
| 02 价格 | 最细合格的售价、Buy Box、List、Deal、Coupon 等实际返回序列 | 当前或历史快照作锚点；价格事件与促销、Listing、BSR、评论和可见性对齐；未返回的价格口径不画线 |
| 03 订单 | 同对象供应商销量/订单估算的最细合格序列 | 月/周估算按真实粒度作图；若无直接销量，展示与需求/销量直接关联的 BSR、价格、评论发表量、可见性和竞争事件信号，并明确其不是订单数 |
| 04 BSR | 最细合格 BSR 数值序列 | 历史序列没有类目/node 标签时只称 BSR 数值趋势；采集时点大/小类排名另作快照锚点，不能反写到每个历史点 |
| 05 评分 | 星级、累计评分数、合格相邻差分 | 断点、倒退和字段刷新必须可见；用逐条评论或快照解释，不把字段修订写成真实评价变化 |
| 06 评论 | 可审计逐条评论、本地日期筛选、去重、主题、星级和趋势 | 服务端时间过滤失效但日期语义有效时，全页采集后本地筛选；覆盖不足时只称已返回样本，不伪造总体比例 |
| 07 变动 | 可观察事件、跨模块因素搜索、L1/L2/L3、行动与验证时间线 | 必须组织结果信号、直接因素、间接因素、替代解释与可推翻验证；评论比例代理只有分子/分母同口径时才显示 |

## 图表、事件与因素表达

- 每张图或证据卡都显示标题、对象、期间、实际粒度、单位、数据性质、来源摘要和限制。`null`、空集合、截断或未结束期不得显示为零。
- 日级价格、订单、BSR、评分数据确实可用时，保留完整日级数据、日期输入/缩放和以真实首尾有效值计算的选区比较。非日级图不得伪装日级缩放能力。
- 图表之后必须有本次证据驱动的读图、事件/因素解释、证据引用、替代解释和限制；不能只交付图形。
- 材料性拐点通过既有图表或第 07 部分事件时间线展示。Tooltip/事件记录应包含前后值、观察时间、来源、证据 ID、实际粒度、`directFactors`、`indirectFactors`、`impact`、同口径 `comparison`、`recommendations` 和 `alternativeExplanations`。
- `directFactors` 只能写同对象、可观察且可时间对齐的事实；`indirectFactors` 是有业务逻辑与证据支持的候选机制；不得编造贡献百分比。预测必须与观察事实分层，并写明条件和失效证据。
- 图表优先，文字用于定义、读图、事件/因素推理与限制。广告/流量、新品等结果只能作为概览、既有图表事件或就近补充，不得创建第八部分。

## 特别限制

- SellerSprite 销量/订单字段必须标注供应商估算，不能写成 Amazon 真实订单、送达量、广告订单或销售额事实。
- 评论主题、情感、比例和趋势均为分析派生；只展示匿名 evidence ID、日期、星级和最小充分摘录，不展示评论者身份画像。
- “同期可见评论 / 供应商估算销量比例代理”只有在分子与分母满足同站点、同对象、同期间、同粒度、单位明确时可计算；它不是真实留评率、购买 cohort 转化率或订单留评率。
- Listing 的当前快照、可比历史快照与平台实际修改时间必须分开。不同来源标题或图片 URL 的差异不能自动构成修改事件。
- BSR 越小越好；只有历史字段实际携带层级时，才将父/子类目作为历史独立序列。
- 不使用 CDN、模板模拟数据、虚构证据 ID、未经证据支持的预测或离线伪造图片。图片能力只写 `embedded | remote_reference | metadata_only | unavailable`。

## 发布验收

- [ ] 基于模板副本，`templateMode=false`；七个一级部分、顺序、导航、DOM id 和核心交互均保留。
- [ ] 没有模板预览 ASIN、数字、主题、摘要、结论、图片或事件记录。
- [ ] 每一部分以最细合格直接原料或有边界的关联证据回答问题；没有因预设日级字段为空而只留空图。
- [ ] 对象、站点、父子体、变体、类目、时间、时区、实际粒度、币种、dataset version 与本地加工规则可追溯。
- [ ] 图表、正文、事件、因素链和证据引用使用同一对象范围、期间、粒度和版本。
- [ ] 估算、代理、派生、本地加工、当前未结束期、字段修订、参数失效、缺口和不可比性没有被隐藏或补零。
- [ ] HTML 为 UTF-8，能独立打开；没有 CDN 或其他外部脚本依赖，远程图片依赖已明确标识。
