# 评论异常筛查决策辅助

## 候选门

候选定义为冻结 ASIN 范围和一个已完成时间桶。只有以下条件全部满足时可标 `screen_positive`：

1. 至少两个不同描述性信号族在同一桶或预先声明的滞后桶一致；
2. 基线可比，或唯一限制明确且不可能合理产生该模式；
3. 分页覆盖、父子映射、字段定义和时间桶通过检查；
4. 至少记录一个实质替代解释和一个反向检查；
5. 没有作出真实性、刷评、操纵、违规、主体或因果推断。

范围或覆盖失败时使用 `explained_by_scope_change | insufficient_coverage | not_calculable`，不强行生成异常矩阵。

## 反向检查

| 信号 | 最低检查 |
|---|---|
| 评论/销量估算比例代理 | 销量估算定义、同对象/期间、预先声明滞后、评论发布延迟、用户参考线来源 |
| 日期集中 | 完整分页、时区和桶边界、小样本、活动/Vine/变体合并等替代解释 |
| 星级或主题构成变化 | 筛选、codebook、分母和字段覆盖是否稳定 |
| VP/Vine/媒体/语言构成 | 字段缺失率、schema 变化、采样和筛选变化 |
| 近重复 | 原语言、确定性方法、常见短语或转载内容替代解释 |
| 父子体不连续 | 前后身份登记、子体纳入规则和评论池范围 |
| 负评论增量 | 累计数修订、评论删除、平台清理、父子聚合变化、工具刷新和数据错误 |
| 价格/Coupon/BSR 同期变化 | 同期来源链、季节、库存不可见、排名模型和其他事件 |

用户提供的 2%–3% 只能标为 `user_supplied_heuristic`，用于触发检查，不能写成已验证行业正常值。即使多个信号一致，仍只形成描述性候选和最低验证请求，不建议举报或惩罚动作。
