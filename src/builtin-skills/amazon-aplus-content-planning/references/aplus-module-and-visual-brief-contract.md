# A+ 模块与视觉 brief 方法

## 一、模块为什么存在

每个模块都要回答一个具体用户问题，并说明：

- 功能角色：首屏识别、功能解释、场景、步骤、对比、品牌故事或 FAQ；
- 本模块要解决的理解问题；
- 支撑文案与视觉的产品事实、关键词和 VOC；
- 基于事实的短文案；
- 所需源资产、权利情况和视觉目的；
- 不得加入的宣称、部件、徽章、效果或场景；
- 当前能否形成生产 brief，缺什么以及责任方。

功能角色不等于 Amazon 当前后台模块名称。实际模块映射必须由运营方根据账户和站点核验。

## 二、对比模块

只有满足以下条件才规划对比：

1. 比较对象明确且合法；
2. 比较字段有相同定义、单位和期间；
3. 每个单元格都有事实依据；
4. 缺失值保持缺失，不填成“无”；
5. 不用主观“更好”代替具体差异；
6. 变体和其他产品没有被混写。

不满足时，改为单产品功能解释，或说明需要补充的证据。

## 三、视觉资产 brief

每项资产至少包含：

- 服务的模块名称/顺序；
- 要让读者看懂什么；
- 必须出现的产品、动作、环境和细节；
- 画面必须忠实呈现的事实；
- 不得添加的部件、徽章、文本、效果或场景；
- 用户图片或品牌资产路径及权利确认；
- 目标语言与文字叠加要求；
- 跨模块必须保持的产品外观、色彩、字体、光照和背景语言；
- 单资产及跨模块验收方式；
- 失败时仅需返工的范围、冻结内容和责任方。

“现代、高级、转化感”不能替代视觉目的和验收条件。

## 四、跨模块一致性与局部返工

1. 产品身份锚点必须来自用户确认且权利明确的现有资产；没有锚点时停止生产并要求补充。
2. 所有模块都引用同一锚点，但可以根据沟通任务改变构图。
3. 产品形态、颜色、材质、部件、比例、色彩系统、字体体系、光照方向和背景语言逐项验收。
4. 单一模块失败时，只返工受影响资产并冻结已通过模块；返工后重新检查跨模块一致性。
5. 固定模块数、像素、字号、安全区或后台名称属于当前运营核验项，不能把历史素材当作平台事实。

## 五、责任与交接

- 文案问题交给 Listing 文案开发；
- 图片生成和编辑交给第 04 视觉内容专家；
- 账户资格、模块映射、尺寸和上传交给运营；
- 高风险宣称和资产权利交给相应合规或权利负责人。

跨责任方追踪依靠清晰的模块名称/顺序、资产名称/路径、产品事实来源和验收项，不为此额外制造一套通用对象编号。
