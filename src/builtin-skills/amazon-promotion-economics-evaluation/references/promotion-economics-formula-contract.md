# 促销增量经济评估方法

## 1. 基线

取得专家 14 或用户验证的活动前单位贡献 `C0`、可比基线销量 `Q0`、币种、期间、商品范围和版本。缺 `C0`、`Q0` 或口径不一致时，不能计算保本销量倍数。

## 2. 活动后单位贡献

从批准或待评估的有效成交价出发，逐项扣除仅因本次促销新增或变化的成本：

`C1 = 活动后单位收入 - 活动后单位成本 - 每兑换单费用 - 其他单位增量成本`

固定活动费 `F` 不应混入单位贡献。折扣、Coupon、会员价等叠加顺序必须有来源；未知时做分支情景，不自定顺序。

## 3. 总贡献与保本倍数

基线总贡献：

`Baseline contribution = C0 * Q0`

促销情景总贡献：

`Scenario contribution = C1 * Q1 - F`

维持基线总贡献所需销量：

`Q1_break_even = (C0 * Q0 + F) / C1`

保本销量倍数：

`Break-even multiple = Q1_break_even / Q0`

当 `C1 <= 0` 时不存在有限保本销量倍数；不能用“多卖一点”掩盖结构性亏损。

## 4. 情景设计

销量情景必须明确是假设，不能调用市场趋势直接改写。建议至少检查：

- 兑换率变化；
- 固定费是否发生；
- 每兑换单费用与履约/退货增量；
- 价格/折扣叠加差异；
- 活动前后单位贡献；
- 达到用户目标需要的销量倍数。

## 5. SIF 阈值工具的边界

`market_estimate_profit_threshold` 只提供供应商费率/汇率口径下的探索性采购成本上限。调用时所有正式参数都要来自可信材料并保留直接依据；输出不能替代专家 14 的利润真相或促销决定。

`ops_get_asin_sales_trend` 及 SellerSprite/Sorftime 趋势只提供外部需求背景，不替代 `Q0`、真实订单、兑换、蚕食或增量销量。三方只有对象和定义一致时才比较，绝不平均。

## 6. 沟通

报告展示输入、公式、带单位步骤、结果、假设、敏感项和结论上限。不要把“保本倍数”写成销量预测，也不要把供应商阈值写成可执行采购或定价结论。
