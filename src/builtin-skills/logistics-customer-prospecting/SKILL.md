# 物流客户拓客

## 目标与完成定义

把“找一批需要物流服务的客户”转成可追溯、可验证、可交给业务跟进的企业线索。完成时应能回答：

1. 为什么该企业符合本次物流客户画像；
2. 平台店铺、品牌、网站和法定主体之间是什么关系；
3. 主体是否已经唯一确认，哪些证据支持或冲突；
4. 哪些电话、邮箱或官网入口是公开商务联系方式；
5. 哪些联系方式可进入人工首联，哪些需验证、排除或转人工；
6. 本批次的覆盖率、唯一主体率、可联系率、成本和失败原因是什么。

完成不代表对方一定有运输需求、联系方式一定可达或已经同意营销。正式状态只能到 `ready_for_human_outreach`，不得自动升级为商机或客户。

## 使用边界

### 适用对象

潜在客户通常是有跨境运输、报关、仓储、尾程或履约需求的制造商、贸易商、品牌方、跨境卖家和出口企业。用户明确要求渠道合作时，也可寻找海外代理、分销商或物流合作伙伴，但必须与“潜在货主”分开标记。

本 Skill 不用于：

- 采购方寻找或尽调工厂；该任务交给 `supplier-sourcing-readiness` 或 `supplier-evaluation-and-due-diligence`；
- 比较用户已有货运报价；该任务交给 `cross-border-freight-option-comparison`；
- 登录平台后台、绕过验证码或访问控制；
- 购买、拼接或使用泄露的联系人名单；
- 根据姓名或域名规则猜测邮箱；
- 自动群发、自动外呼、自动添加社交好友或代表用户发送消息；
- 把平台销量、营收区间或供应商标签写成真实货量、运输频次或成交意向。

### 合法输入

- 用户提供的物流服务范围、优势线路、运输方式、起运地、目的地、货物限制和客户画像；
- 用户明确给出的品类、国家、平台、关键词、排除条件、样本量、时间窗口和预算；
- 用户上传或可信上游 `outputs/` 中已有的企业、店铺、品牌或联系人记录；
- 当前 Agent 已注入且获授权使用的供应商平台采集、企业信息和公开网页工具；
- 业务人工确认的联系结果、拒绝联系状态和 CRM 历史。

不得读取或要求用户把 API Key、Cookie、密码写入 Prompt、Skill、工作簿或日志。密钥只能由产品运行时的 Secret Manager 注入。

## 工作区约定

- `uploads/`：只读业务输入和既有名单；
- `temp/sales-prospecting/<run-id>/`：查询计划、原始结果索引、实体候选和去重草稿；
- `outputs/sales-prospecting/<run-id>/`：唯一正式交付；
- 原始平台记录、法定主体、联系方式证据和销售跟进分层保存；
- 电话和邮箱只进入受控交付或 CRM，不复制到源代码、项目说明、模型调试日志或公开报告。

## 启动检查

实际采集前至少确认：

1. 物流服务类型与优势线路；
2. 目标企业类型、地区和产品/行业；
3. 候选来源，例如 Alibaba、Amazon、Made-in-China 或企业官网；
4. 关键词及排除词；
5. 样本上限、翻页上限或费用上限；
6. 输出格式与接收业务团队；
7. 是否只做线索准备，还是还要生成待人工审核的话术草稿。

缺少服务范围或客户画像时，先输出 ICP 澄清表，不启动可能产生费用的采集任务。用户已经明确品类、数量和数据源时，可以直接执行相应范围，不重复确认。

## 外部工具路由

只使用当前 Agent 实际注入的工具。工具不存在、无权限、返回 Schema 不明或结果截断时，明确降级，不声称已经采集或补全。

### 八爪鱼 MCP：平台线索发现

八爪鱼只负责发现店铺、供应商或企业线索，不承担联系方式终态。

使用约束：

1. 先用 `search_templates` 查找模板，并检查模板输入与输出字段是否满足当前平台、对象和关键词；模板名称相似不等于语义正确。
2. 只有用户已授权实际采集并给出范围时，才可用 `execute_task` 创建任务；设置唯一 `taskName`、关键词、翻页/记录上限和预算边界。
3. `execute_task` 超时或响应不确定时，先用 `search_tasks` 按唯一任务名恢复；不得直接重建并重复计费。
4. 用 `get_task_status` 查询状态；任务完成后以 `export_data` 按任务 ID、`lotNo` 和分页导出。
5. `start_or_stop_task` 会改变已有任务状态，必须得到用户对该具体任务的明确授权。
6. 禁止调用 `redeem_coupon_code`。
7. 保存模板 ID、输入 Schema、参数摘要、任务 ID、`lotNo`、分页范围、状态和行数；不保存密钥。

模板没有电话、邮箱或官网字段时，按 `not_provided_by_discovery_source` 记录，不得从空值推断“企业没有联系方式”。

### 企查查 MCP：中国法定主体与联系方式

企查查只处理能够合理映射到中国法定主体的候选。允许工具限定为：

- `get_company_by_query`
- `verify_company_accuracy`
- `get_company_registration_info`
- `get_contact_info`

执行顺序：

1. 平台英文名、店铺名或品牌名先进入实体证据解析；不能只把英文名直传后把“无匹配”写成企业不存在。
2. 用中文法定主体候选调用 `get_company_by_query`。
3. 只有唯一候选，且名称、英文名、地区、地址、成立日期、官网或统一社会信用代码等证据足以支持时，状态才能进入 `entity_unique_match`。
4. 用 `get_company_registration_info` 或 `verify_company_accuracy` 复核主体。
5. 仅对唯一主体，以法定名称或统一社会信用代码调用 `get_contact_info`；电话查询应使用 `excludeInvalidPhone=true`。
6. 无匹配、多候选或关键证据冲突时停止联系方式调用，进入人工研究或复核队列。

`excludeInvalidPhone=true` 仅表示过滤企查查已知无效号码，不证明其余号码在职、归属正确、可接通或适合营销。

### 企业官网与公开目录：联系方式交叉验证

可检查企业官网的 Contact、About、Imprint、Dealer、Wholesale、OEM/ODM 页面，以及公开展会目录、制造商档案或授权文件。只提取页面明确公开用于企业联系的内容，并保存 URL、访问日期、页面语境和联系方式角色。

不得绕过登录、验证码、robots/访问限制，不得从私人社交账号、泄露数据库或非公开文档中提取信息。网页只能证明页面在该时间公开了某项陈述，不能单独证明法定主体或联系方式当前有效。

## 标准工作流

### 第一步：建立物流客户画像

记录：

- `service_profile_id` 和版本；
- 运输模式、优势线路、起运/目的国家或城市；
- 可承接和禁止承接的货物类型；
- 目标企业角色、产品品类、规模信号和语言；
- 必须条件、加分条件和排除条件；
- 业务团队希望验证的假设。

没有直接运输需求证据时，只能写“符合潜在客户画像”，不能写“正在寻找货代”或“每月有某个货量”。

### 第二步：设计并执行发现批次

将品类与客户类型转成查询词，保留语言、平台、国家、页数和排除词。每批次使用可恢复的 `run_id` 和唯一任务名，先做小样本，再根据相关率和成本决定是否扩大。

原始发现记录不得覆盖，至少保存平台记录 ID、店铺/公司名、链接、地区、产品、平台年限/认证等原始字段和采集时间。

### 第三步：筛选产品与物流适配

分别判断：

- 产品/行业是否命中；
- 企业角色是否可能产生跨境物流需求；
- 地区与优势线路是否匹配；
- 平台记录是否仍有效；
- 是否命中排除条件。

每项给出直接依据和限制，不用平台营收区间推算真实货量。

### 第四步：解析法定主体

建立从平台记录到法定主体候选的证据链。优先信号包括中英文名称对应、官网域名、地址、成立日期、品牌、ICP、展会目录、认证报告和统一社会信用代码。

不同信号冲突时并列保存，不平均、不静默选择搜索结果第一名。实体状态和最低证据要求见 `references/prospecting-evidence-contract.md`。

### 第五步：补全并分级联系方式

每个联系方式单独成行，保留：

- 联系值和标准化值；
- 类型与角色；
- 来源、URL、获取时间和页面语境；
- 主体关系；
- 置信度、最新性和验证状态；
- 建议用途或排除原因。

优先顺序通常为：官网销售/合作邮箱或 WhatsApp、多来源一致的企业座机、企业域名邮箱、仅企业数据源收录的座机/手机号、免费邮箱。`support@`、`privacy@`、`legal@`、个人手机号和免费邮箱不得默认作为高优先级销售入口。

不得猜测邮箱格式，不得把同一电话号码的不同格式当成多个联系人。

### 第六步：去重、抑制和质量分层

先按统一社会信用代码或已验证法定主体去重，再按标准化域名、电话和邮箱合并联系方式证据。相同联系值由不同来源支持时保留多条 Evidence，但销售视图只显示一个标准化入口。

进入销售视图前检查全局拒绝联系名单、历史无效记录、疑似代记账/注册代理、私人用途和来源限制。命中抑制规则的记录保留审计，但不得进入首联名单。

不要用一个不透明总分掩盖问题。至少分别给出：客户画像适配、主体置信度、联系方式置信度和数据新鲜度。

### 第七步：形成销售交接

只有同时满足以下条件才可标记 `ready_for_human_outreach`：

- 客户画像适配理由可追溯；
- 法定主体唯一，或用户明确接受仅按公开品牌/官网联系；
- 至少一个未被抑制的公开商务联系方式；
- 来源、获取日期、验证状态和限制完整；
- 下一步、负责人和人工复核要求明确。

本 Skill 可生成待人工审核的话术 brief，但不得发送。话术不得声称知道对方货量、当前物流商、价格痛点或采购计划，除非有直接证据。

### 第八步：复盘批次

按 `references/prospecting-evidence-contract.md` 计算发现相关率、唯一主体率、可联系企业率、待人工复核率、异常联系方式率和每个唯一可联系企业成本。失败记录不能静默丢弃。

## 状态机与失败关闭

主路径：

```text
discovered
  -> profile_fit_checked
  -> entity_evidence_found
  -> entity_unique_match
  -> registration_verified
  -> contacts_enriched
  -> contacts_reviewed
  -> ready_for_human_outreach
```

异常分支：

- `no_profile_fit`：保留排除理由，不进入主体补全；
- `no_entity_evidence`：进入人工研究，不调用联系方式；
- `entity_no_match`：保留候选和查询范围，不写成企业不存在；
- `entity_multiple_matches`：不得选择第一名，进入人工复核；
- `entity_evidence_conflict`：保持主体拆分，停止联系补全；
- `contacts_not_found`：记录已查来源与缺口，不猜测；
- `contacts_need_validation`：可进入验证队列，不进入自动触达；
- `do_not_contact`：所有渠道停止营销并记录来源与生效时间；
- `provider_timeout_or_unknown`：先恢复既有任务，无法恢复时停止并报告；
- `provider_schema_changed`：隔离响应，不能按旧字段继续解析。

## 正式交付

使用 `assets/templates/logistics-prospecting-delivery-template.md`，至少输出：

1. `lead-register`：一行一个企业，包含画像适配、唯一主体、首选联系方式、状态和下一步；
2. `contact-evidence`：一行一个联系方式来源记录；
3. `entity-evidence`：平台记录、主体候选、证据、冲突和匹配结论；
4. `collection-runs`：模板、查询、范围、任务、行数、成本和错误；
5. `manual-review-queue`：多候选、冲突、异常联系方式和责任人；
6. `do-not-contact`：拒绝联系和抑制记录；
7. `batch-summary`：质量与成本指标、限制和下一轮建议。

若用户要求 Excel、CSV、飞书多维表格或 CRM 导入，保持上述实体分层和 `lead_id`/`company_id` 外键，不把多个电话或邮箱塞入一个不可追溯的文本单元格。

## 质量门

- 实际使用的工具、输入范围和返回状态均可追溯；
- 八爪鱼任务可按唯一任务名恢复，没有因超时重复创建；
- 发现源缺少联系方式没有被解释为企业无联系方式；
- 平台名称到法定主体有逐项证据，非唯一主体没有进入企查查联系方式调用；
- 电话、邮箱和网址逐条保存来源、日期、角色、验证和抑制状态；
- 个人或免费邮箱、个人手机号、疑似代记账号码没有被默认列为高优先级；
- 缺失、冲突、无匹配、无效和真实零值没有相互替代；
- 联系方式未被写入源代码、公开文档或模型日志；
- 未自动发送消息、外呼、建群、加好友或创建后台营销任务；
- 正式交付能从销售视图回溯到实体和联系方式 Evidence；
- 批次指标使用明确分母，目的性样本没有被外推成总体成功率。
