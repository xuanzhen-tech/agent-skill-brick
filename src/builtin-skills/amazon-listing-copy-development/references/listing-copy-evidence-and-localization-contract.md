# 文案证据与本地化合同

## 一、宣称等级

| 等级 | 定义 | 正文处理 |
|---|---|---|
| `direct_fact` | 来源明确陈述且适用范围清楚 | 可准确重述 |
| `bounded_benefit` | 可由直接事实合理解释，但必须保留条件 | 允许谨慎表达并引用事实 |
| `user_asserted` | 用户明确提供、未独立核验 | 可按用户事实使用，账本标明来源 |
| `needs_confirmation` | 含义、单位、变体或条件不清 | 不进入正式文案 |
| `prohibited` | 无证、误导、敏感或明确禁止 | 删除 |

不能仅凭评论、关键词、竞品表达或供应商流量字段证明产品性能。

## 二、句子证据映射

每个事实性句子至少记录：

| 字段 | 含义 |
|---|---|
| `copy_id` | 字段内稳定句子 ID |
| `field` | 标题、要点、描述或后台词候选 |
| `copy_text` | 最终目标语言文本 |
| `fact_ids` | 支撑事实 |
| `keyword_ids` | 使用的关键词约束 |
| `claim_level` | 宣称等级 |
| `variant_scope` | 适用变体 |
| `risk_flags` | 合规、单位、比较、绝对化或歧义风险 |
| `review_status` | `ready`、`needs_human_review` 或 `blocked` |

证据账本使用两类记录：

| 记录类型 | 必填追踪字段 | 四轴处理 |
|---|---|---|
| `input_evidence` | `evidence_id`、来源路径或工具、使用字段、版本/期间、限制 | 原样保留输入证据四轴 |
| `agent_output` | `copy_id`、`parent_evidence_ids`、Fact/Keyword ID、审阅状态 | 使用本层四轴；文案通常为 `source_type=agent`、`transformation_type=coding` |

`parent_evidence_ids` 必须指向账本中真实存在的输入记录。文案文本是 Agent 产物；不得把它重新标成来源原始事实，也不得用本层四轴覆盖输入原四轴。

## 三、安全表达

- 把精确事实写清楚，不用空泛“高品质”替代规格；
- 利益表述必须能够从事实合理解释，并保留使用条件；
- 对“最强、第一、永久、零风险、保证结果”等绝对化语言要求直接证据和当前适用规则，否则删除；
- 比较性表述必须说明比较对象、指标、期间和证据；
- 认证、医疗、安全、环保和法律宣称需要明确文件及适用范围；
- 评论痛点可以帮助选择沟通主题，不能证明产品已经解决该问题。

## 四、多语言质量门

对源语言与目标语言逐项核对：

1. 产品身份是否一致；
2. 数字、单位、时间、数量和兼容型号是否一致；
3. 条件、否定、例外和适用范围是否保留；
4. 事实是否被目标语言夸大或弱化；
5. 关键词变形是否保持原意和自然表达；
6. 品牌语气是否一致；
7. 是否出现目标市场可能误解的缩写、量制或含糊代词；
8. 高风险句子是否标记人工审核。

“读起来流畅”不能替代含义一致性。

## 五、版本差异

需要多个版本时，记录每个版本改变的唯一主要角度，例如：

- 信息顺序；
- 利益主题；
- 关键词自然变体；
- 品牌语气。

不得让不同版本同时改变产品事实、价格、促销、适用范围和多个卖点，再声称可以判断哪个因素有效。
