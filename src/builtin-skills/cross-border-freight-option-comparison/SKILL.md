# 跨境货运方案比较

## 何时使用

当用户提供两份或更多货运报价，希望在同一批货物、同一运输区间和可核对的服务条件下复核计费并比较方案时使用。

典型请求：

- “比较这三家货代报价，但不要帮我订舱。”
- “分别按各报价的体积重、W/M 和最低收费规则重算。”
- “告诉我为什么这两份空运报价不可直接比较。”
- “把时效定义、附加费、有效期和排除项整理出来。”

## 唯一报价来源

货运价格与报价条款只能来自：

1. 用户在当前任务中明确提供的报价单、邮件摘录、表格、图片或文字确认。
2. `uploads/` 中用户上传的只读报价材料。
3. 可信 `outputs/` 中明确标识为用户报价整理结果、带版本和证据定位的正式产物。

不得主动从 Web、浏览器、SP-API、ERP、WMS、领星、17TRACK、货代网站或其他 API/MCP 获取、补齐或替换报价，也不调用 `sif_mcp`、`sellersprite_mcp`、`sorftime_mcp`。17TRACK 是物流轨迹服务，不是运价来源。SIF、SellerSprite、Sorftime 都没有可替代用户正式运价、报价条款或运输时效的能力，其市场信号不能替代用户报价。

本 Skill 的报价比较不调用三个 MCP 或其他外部业务工具。用户另行要求市场需求背景时，应交给上游分析能力；本包不得把任何外部返回挂接到运价、报价条款或时效排名。

## 不得使用的场景

本 Skill 不得：

- 向货代询价、修改报价或代表用户谈判。
- 订舱、下单、付款、提交委托、预约提货或安排仓库。
- 查询或持续监控物流轨迹。
- 使用统一的体积重除数、W/M、最低收费或附加费规则覆盖原报价。
- 自行补充燃油、旺季、偏远、报关、查验、仓储或其他费用。
- 计算关税、增值税、HS 编码、清关要求或反倾销结论。
- 计算利润、贡献、库存资金占用或完整运输经济。
- 在后台定时刷新、提醒或追踪报价有效期。

## 责任边界

### 本 Skill 单一负责

- 登记并转录用户报价的原始事实。
- 判断报价是否指向同一货物基准、运输区间和服务范围。
- 按各报价自身规则复核实际重、体积重、计费重、W/M、最低收费和附加费。
- 区分原始报价事实与本 Skill 派生的复核/比较结果。
- 输出可比、条件可比或不可比的结论与最小补充问题。

### 交给其他专家

- HS 编码、税率、清关、反倾销：专家 09 单一拥有。
- 运输经济、利润、贡献、资金占用、业务选择边界：专家 14。
- FBA 资料就绪：`amazon-fba-shipment-readiness`。
- 补货执行准备：`amazon-replenishment-execution-readiness`。
- 订舱、付款、轨迹监控和异常处理：人工或专用执行系统。

本 Skill 可以比较“报价所列费用”，但不能把最低报价自动解释为最佳商业方案。

## 工作区约定

- `uploads/`：只读报价原件。
- `temp/`：OCR 草稿、字段对齐和复核计算；不得覆盖报价原件。
- `outputs/`：正式报价比较报告。
- 不写入密钥、令牌、Cookie、邮箱密码或货代系统凭据。

## 任务契约

开始前明确：

- 比较任务 ID。
- 报价数量和报价版本。
- 货物批次、件/箱/托范围。
- 起运地、目的地和运输区间。
- 运输模式及服务范围。
- 用户希望比较的维度。
- 是否只做费用复核，还是需要把商业经济判断交给专家 14。

无法确认同一货物基准或同一运输区间时，不得生成价格排名。

## 报价证据与比较判断

每个报价事实保留报价方、报价 ID/版本、签发与有效期、货物及运输区间、服务范围、原值/单位/币种、文件页码或单元格定位，以及报价中的限制。外部市场或销量背景不能替代报价金额、报价条款或时效依据。

计算和比较必须让读者能复核：

| 判断 | 直接依据 | 为什么这样处理 | 限制或不可比原因 |
|---|---|---|---|
| 计费重、最低收费或附加费复核 | 报价原规则和参与计算的原值 | 展示带单位代入、进位和舍入 | 规则缺失、单位未知、条件未触发或无法确认 |
| 两份报价是否可比 | 同一批次、区间、服务段和有效窗口 | 说明哪些条件已对齐 | 货物基准、服务范围、时效定义或费用边界不同 |
| 允许比较的成本或时效差异 | 可比报价及复核结果 | 展示差异，不隐藏排除项 | 汇率、税费、条件性费用或时效事件未知 |
| 最终建议边界 | 上述报价事实和比较结果 | 说明适用场景及理由 | 商业经济判断转交专家 14，执行由人工完成 |

缺失不是零；冲突值必须并列，不能平均或自行选择。任何价格或时效排序前，都要核对报价对象、有效时间、单位/币种、计费规则和服务口径。

## 报价事实卡

每份报价必须尽可能提取：

### 身份与有效性

- 报价 ID 与版本。
- 报价方。
- 签发时间。
- 有效期起止。
- 适用出运窗口。
- 报价状态：正式、草案、估算或用户未知。

### 货物基准

- 件数、箱数、托盘数。
- 每个计费对象的长宽高及单位。
- 实际重量及单位。
- 是否实测、估算或由报价方采用。
- 可堆叠、危险品、带电、超长/超重等条件；仅按原文。

### 运输区间

- 起点和终点。
- 门到门、门到港、港到港、港到门或原报价自己的定义。
- 运输模式和主运段。
- 提货、出口操作、主运、进口操作、派送各段是否包含。
- 交付节点或仓库条件。

### 计费规则

- 实际重。
- 体积重公式和除数。
- 计费重选择规则。
- W/M 定义与使用范围。
- 最低计费重量、最低计费体积或最低收费。
- 进位、舍入和计费单位。
- 分档单价和适用区间。

### 费用与排除

- 基础运费。
- 每项附加费的名称、计费基数、费率/金额和币种。
- 已包含费用。
- 未包含费用。
- 条件性费用及触发条件。
- 税费、清关、查验、仓储等是否只作为排除项出现。

### 时效

- 原始时效数值/区间。
- 自然日或工作日。
- 起算事件。
- 截止事件。
- 班期或截单条件。
- 时效承诺、估算或参考的性质。
- 明示排除：清关、查验、天气、旺季、偏远派送等。

缺失信息必须写 `not_stated`，不得使用行业惯例补齐。

## 按原报价规则复核

### 实际重量

实际重只能来自用户材料或报价原件。多箱时只有在报价规则以总重计费且箱级单位一致时才可求和。

记录：

- 原始箱级或总实际重。
- 原始单位。
- 求和范围。
- 是否存在重复或缺箱。

不得以商品净重估算装运毛重。

### 体积重量

只有报价明确给出公式/除数时才计算。示意结构为：

`体积重 = 报价定义的尺寸组合 ÷ 报价定义的除数`

这不是统一公式。必须逐报价保存：

- 长宽高取值和单位。
- 按箱计算还是总体积计算。
- 除数及其适用单位。
- 是否逐箱进位。
- 舍入规则。

报价未声明除数时，体积重为 `not_computable`，不得默认使用 5000、6000 或任何行业常数。

### 计费重量

计费重必须按报价原文规则。只有原报价明确采用两者较大值时，才可使用：

`计费重 = max(实际重, 体积重)`

若报价使用阶梯、逐箱比较、最低计费重或其他规则，必须逐字映射并按其执行。规则缺失则 `not_computable`。

### W/M

W/M 只按报价材料自己的定义使用。必须确认：

- W 的重量单位与换算基准。
- M 的体积单位。
- 比较是在总货物、每票还是每计费单元进行。
- 取大、取小或其他选择规则。
- 最低计费单位和进位规则。

任一项缺失时不得套用“1 吨对 1 立方米”等通行惯例。

### 最低收费

最低收费的处理顺序必须来自报价原规则：

- 先算基础费后取最低收费；
- 最低收费是否包含某些附加费；
- 每票、每批、每箱或每航段适用；
- 币种和税务状态。

规则未声明时，不得自行决定最低收费与附加费的先后。

### 附加费

每项附加费单独列示：

- 固定金额、按重量、按体积、按票、百分比或其他基数。
- 触发条件。
- 最低/最高值。
- 币种。
- 是否已含税。
- 是否计入最低收费。

条件未满足或未知时，写 `conditional_unknown`，不得记为零。

## 币种和单位

### 币种

- 保留报价原币。
- 同币种且费用范围一致时，才可直接比较报价金额。
- 不同币种时，默认不可做金额排名。
- 用户若提供明确汇率、来源、时点和换算授权，可以额外展示换算列，但必须保留原币并把经济判断交给专家 14。
- 不从外部自动查询汇率。

### 单位

允许为展示进行可逆换算，但必须记录：

- 原值和原单位。
- 换算因子及来源。
- 目标单位。
- 精度和舍入规则。
- 换算结果。

无法证明单位含义时不得换算。

## 可比性门

只有以下条件均满足，才能直接比较：

- 同一货物批次或有明确等价基准。
- 实际重/尺寸输入范围一致。
- 运输区间和服务段一致。
- 报价在计划出运期有效。
- 计费规则可复核。
- 费用包含、排除和条件性费用可对齐。
- 币种相同，或用户提供合规换算基准。
- 时效的起止事件、日历口径和排除项可对齐。

若只有补齐明确条件后才可比，列出条件、责任人和对结论的影响；若关键条件不可比或报价规则缺失，停止价格/时效排名，只并列展示事实与差异。

## 标准工作流

### 第一步：逐份登记报价原件

每个报价版本分别登记报价方、版本、日期和原件定位。修订报价不能覆盖旧版本。

### 第二步：建立货物与区间基准

确认比较对象、实际重、尺寸、箱/托范围、起终点和服务段。差异必须显式列出。

### 第三步：转录原始规则

先转录，后计算。对看不清或未写明的文字标记 `unreadable` 或 `not_stated`。

### 第四步：逐报价复核

在每份报价内部按自身规则计算实际重、体积重、计费重、W/M、最低收费和附加费。保留所有中间步骤。

### 第五步：费用范围桥接

建立包含/排除/条件性费用矩阵。不能用零填充未报价项目。

### 第六步：时效定义桥接

对齐起算、截止、自然/工作日、班期和排除项。定义不同则仅并列展示。

### 第七步：通过可比性门

先判断可比性，再比较金额或时效。不可比时只输出差异和最小补充问题。

### 第八步：生成正式报告

使用 [比较报告模板](assets/templates/freight-option-comparison-report.md) 输出报价事实、复核步骤、可比性和人工下一步。

## 封闭失败

以下情况不得生成排名：

- 报价不是用户提供或无法追溯到用户材料。
- 货物重量/尺寸基准不同且无法桥接。
- 运输区间或服务范围不同。
- 报价已过期或有效期未知且用户不确认。
- 体积重除数、W/M、最低收费或附加费顺序缺失，且会改变金额。
- 费用币种不同且没有用户提供的换算基准。
- 时效起止事件或日历口径不同。
- 关键条件需要从 17TRACK、Web 或其他未允许源补齐。

降级报告必须说明：

- 已转录事实。
- 不可比维度。
- 哪个缺口会怎样改变结论。
- 应向报价方询问的最小问题。
- 不得给出排名的原因。

## 输出质量门

写入 `outputs/` 前确认：

- 所有报价均来自用户材料。
- 每份报价的版本、币种、单位、有效期和区间可见。
- 实际重、体积重、计费重、W/M、最低收费和附加费均按原规则。
- 未默认任何除数、W/M 或费用顺序。
- 时效包含起止事件、自然/工作日及排除项。
- 不可比时没有价格/时效排名。
- 关税清关交给专家 09，运输经济交给专家 14。
- 未询价、订舱、追踪、发送或创建后台任务。
- 每项计算与比较均能回到报价原文，并写明公式、差异、限制和下一责任人。

详细规则见 [报价比较合同](references/freight-quote-comparison-contract.md)。
