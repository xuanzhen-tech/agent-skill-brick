# Listing 问题审计方法

## 一、一个问题必须说清什么

每个问题至少包含：

- 标题、要点编号、描述或后台词候选等具体位置；
- 支撑问题的最短必要文本；
- 准确性、字段职责、关键词、清晰度、具体性、一致性、宣称风险或可读性等问题类型；
- 直接使用的产品事实、关键词资料、用户规则或外部研究及原始位置；
- 问题如何影响理解、匹配、信任或发布准备；
- 为什么属于发布前必须修复、高价值修订、局部优化或需要补证；
- 可执行的删除、保留、补充、重排或澄清动作；
- 修复时不得丢失的事实或表达；
- 修改后如何复核，当前仍有什么不确定性。

不要为了凑数量创建问题，也不要用一个泛化问题覆盖多个不同位置。

## 二、影响表述

- “产品身份不清，读者无法在标题中确认对象”是可解释影响；
- “转化率会下降 20%”在没有实验或一方数据时不是可接受影响；
- “关键词重复挤压了尺寸条件，可能增加误解”是可解释影响；
- “Rufus 不推荐”若没有当前可验证证据，不是可接受影响。

## 三、业务优先级

### 发布前必须修复

适用于事实错误、无证高风险宣称、错误变体扩散、产品身份错误或会阻塞下游使用的问题。

### 高价值修订

适用于证据充分，且修复后能明显改善理解、字段角色或关键词匹配的问题。不得附带没有证据的效果百分比。

### 局部优化

适用于不改变事实的局部简化、自然度或信息顺序改进。

### 需要补证

适用于合理怀疑但缺少产品事实、关键词口径、政策或当前版本的问题。

未提供文本、证据或不属于 Listing 文本专家职责的维度，明确说明未评估原因和责任方。

## 四、修复与复核

有效修复动作必须包括：

1. 要改变的具体位置；
2. 允许使用的产品事实和关键词；
3. 不能新增或丢失的含义；
4. 修改后的可观察检查；
5. 若依赖用户或上游资料，明确阻塞条件。

“优化文案”“增强转化”“更自然”不是完整修复动作。

复核时分别说明：问题已消除、部分消除、仍存在，或因缺少新版/事实/政策而无法核验。关闭文本问题不等于证明业务指标改善，业务效果需独立实验或一方数据。

## 五、外部研究证据

若审计实际调用 MCP，保留供应商和精确工具、站点与查询对象、范围、时间、筛选和分页、原始值及结果位置。关键参数要能追溯到用户输入或上游材料。多个供应商只在口径可比时对照，不盲目平均或静默选取。

未返回、未查询、解析失败、缺失或冲突必须直说，不能解释为无问题、零流量、无关键词或 Listing 内容不存在。覆盖不足会降低相关问题和修复优先级的确定性。最终说明哪些是直接证据、Agent 做了哪些判断，以及仍需补充什么。
