# 关键词布局方法

## 一、先确认关键词是否适合产品

同一个词存在多份资料时，不按数值大小直接排序，也不把不同供应商的结果静默平均。依次确认：

1. 站点、语言、产品和变体是否一致；
2. 搜索、流量、购买或竞品词等数据含义是否一致；
3. 查询期间、粒度、单位和估算口径是否可比；
4. 产品事实是否允许使用该词；
5. 词义是否会造成品牌、功能、材质、兼容性或结果承诺误导；
6. 数据覆盖是否足以支持“优先放置”的结论。

不能比较时，按供应商分别呈现。无法核实产品匹配、词义或口径时，暂不放置并说明需要谁补充什么。

## 二、每个候选词要留下什么

对实际进入判断的候选词，记录：

- 来源原词和仅用于匹配的规范化写法；
- 站点、语言、产品和变体范围；
- 用户意图与使用场景；
- 允许该词进入 Listing 的产品事实及原始位置；
- 市场依据：来源、精确工具、查询对象、期间、原始值和结果位置；
- 反证、冲突、缺口与覆盖限制；
- 建议字段、放置目的和是否允许有理由地重复；
- 产品事实、市场依据和用户优先级之间如何形成当前决定；
- 仍需用户或上游确认的事项。

“必放、支持、候选、排除、暂缓”只能作为业务结论，不得替代上述依据。

## 三、字段选择

### 标题

仅放入能清楚识别产品、主要用途或高确定性差异的词。即使搜索证据较强，只要会误导产品身份、变体或适用范围，就不得进入标题。

### 要点

只有产品事实能够支撑对应属性或利益时才放置。不得为了覆盖词而创建不存在的功能、认证、材质、兼容性或结果保证。

### 描述

适合承载需要上下文说明的场景、长尾和条件，但不能成为风险宣称的藏身位置。

### 后台词

这里只输出候选规划。不得声称已写入 Seller Central、已索引或已生效。格式、长度或重复规则未经当前政策核实时，明确列为发布前核验项。

## 四、常见冲突

| 情况 | 处理 |
|---|---|
| 市场证据强，但产品不匹配 | 排除，产品事实优先 |
| 上游结果陈旧 | 保留历史参考，不当作当前需求 |
| 同一词在不同来源或通道方向冲突 | 按来源、通道和期间并列，不平均 |
| 竞品品牌词 | 默认排除，除非用户提供合法且明确的使用依据 |
| 词义多义 | 暂不放置，要求明确目标含义或上下文 |
| 只有用户偏好、无市场证据 | 可列为待验证候选，不称为高需求词 |
| 只有供应商估算且估算口径不明 | 降低结论强度并披露限制 |

## 五、下游交接

交给文案开发 Skill 的每个字段组应包含：

- 推荐词和可接受变体；
- 对应产品事实；
- 使用目的与自然表达边界；
- 市场依据和反证；
- 必须避免的误导含义；
- 是否允许跨字段重复及理由；
- 未解决风险和需要用户确认的事项。

文案开发可以为自然语言调整词序或语法，但不能无记录地改变词义、产品事实或风险判断。

## 六、外部研究证据

实际调用 MCP 时，保留供应商和精确工具、站点与查询对象、范围、时间、筛选和分页、原始值及结果位置。关键参数要能追溯到用户输入或上游材料。

未返回、未查询、解析失败、缺失或冲突必须直说，不能解释为零搜索量、零流量、零竞争或无关键词；只有本次响应明确返回零时，才记录为零。供应商覆盖不足会降低关键词优先级和字段放置结论的确定性。最终说明哪些是直接数据，哪些是 Agent 的归一化、分组或判断，以及仍需补充的资料。
