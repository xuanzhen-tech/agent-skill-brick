# 生图质量门禁

实际生成、编辑或验收图片时读取本文件。门禁用于诚实报告和控制返工，不是平台合规认证。

## 生成前

- 已确认图片用途、数量、尺寸和质量。
- 已建立商品身份锁；没有商品参考图时已声明仅为概念草稿。
- 所有具体规格、功能、配件和声明都有可观察或用户确认的来源。
- 参考图路径、顺序、`role` 和 `preserve` 与提示词编号一致。
- 多张不同职责的图片已拆成独立 generate 调用。
- 用户未授权的额外候选和整套重跑尚未提交。
- 当前用户消息已经明确指定生成数量、编辑目标和范围时，即视为本次操作已确认，不要重复询问；只有新增数量、扩大范围或发起另一轮付费返工时才重新确认。

## 工具状态

- `queued` 和 `running` 不是完成。
- `completed` 才表示该项文件生成成功。
- `partial` 必须分别报告成功和失败项。
- `failed`、`cancelled`、`interrupted` 不得包装成成功。
- 取消运行中批次时保留“上游仍可能继续生成并计费”的提示。

## 单图检查

只有当前模型实际获得图片观察能力时，才可以判断视觉内容。无法看图时只能确认 artifact、文件、尺寸、状态和版本存在，并请用户或具备视觉能力的模型复核，不得宣称画面通过。

视觉检查包括：

- 商品身份：结构、比例、颜色、材质外观、包装和可见标识是否稳定。
- 内容真实性：没有虚构配件、功能、认证、文字、价格或效果。
- 使用合理性：人物、手、商品和环境关系真实且安全。
- 构图职责：画面确实解决计划中的购物者问题。
- 参考纪律：迁移视觉机制，没有复制参考品牌、人物或原文案。
- 文本风险：文字、Logo、数字和单位清晰且与用户事实一致；不可靠时标记为待排版。
- Amazon 主图：仅在适用时检查白底、商品完整、无额外文案和装饰，并明确这不是平台审核。

## 套图检查

- 同一商品在全部图片中保持一致。
- 复用人物时身份一致，姿势可按职责自然变化。
- 每张图职责不同，没有重复卖点或机械复用同一版式。
- 配色、光线和视觉质量形成统一系列。
- 规格、配件、功能和使用场景没有互相矛盾。
- 每张图都是独立 asset，不以拼图代替交付。

## 返工策略

先分类失败原因：

1. 输入缺失：停止付费生成，向用户索要事实或参考图。
2. 提示词局部问题：基于明确 `assetId` 和 `versionId` 调用 edit。
3. 构图方向错误：经用户确认后创建新的 generate 批次。
4. 模型限制：保留当前 artifact，报告限制，不连续尝试相同提示。
5. 工具或网络错误：遵循返回的 `retryable`；结果未知时不自动重试。

不得自动重新生成整套。每次新增候选或付费返工都必须处于用户已确认的数量和范围内。

## 验收记录

最终回复至少列出：

```text
batchId：
assetId / versionId：
本地 path：
工具状态：
已检查项：
未检查或待人工复核项：
是否发生返工及来源版本：
```

不要把“文件已生成”“人工待复核”和“平台已接受”混为同一状态。

## 设计来源

本门禁吸收了用户提供的 MIT Skill“通用-视觉-电商图片生成引擎”中关于单图与套图验收、故障分类和迭代控制的思路，并按当前异步批次、artifact、版本历史和计费安全边界重新实现。
