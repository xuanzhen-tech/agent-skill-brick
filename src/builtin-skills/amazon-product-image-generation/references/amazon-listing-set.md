# Amazon Listing 套图规划

仅当用户要求多张 Amazon Listing 图片时读取本文件。本文件负责选择图片职责，不规定固定产量，也不替代当前 Seller Central 和类目规则确认。

## 数量原则

- 用户给出数量时严格按该数量规划，不得固定补足到七张。
- 用户未给数量时先提出建议和成本范围，默认仍只生成 1 张初稿。
- 同一职责需要多个候选时使用一个 prompt 配合 `count`。
- 主图、尺寸图、场景图等不同职责使用同一次 `ecommerce_image_generate` 中的不同 request，避免串行等待。
- 商品身份、Logo 和品牌风格写入共享 `basePrompt/referenceImages`，场景独有约束和参考图写入对应 request。
- 每个最终结果都是独立 asset，不生成拼图、九宫格或多图合成文件。

## 候选职责

按商品事实和用户目标选择最小必要集合：

|职责|解决的问题|使用条件|
|---|---|---|
|主图|商品是什么|Listing 套图通常优先；遵循主图限制|
|包装与包含物|实际收到什么|用户已确认包装和配件|
|尺寸与适配|大小是否合适|用户提供准确尺寸和单位|
|核心功能证明|为什么值得购买|功能可观察或有用户事实支持|
|结构与细节|做工和材料如何|参考图能清楚支持|
|生活方式|如何在真实环境使用|场景和操作方式可信|
|多场景用途|适合哪些场景|只使用保守且真实的用途|
|决策支持|如何选择、安装或维护|有准确步骤、兼容性或保养事实|

数量不足时保留主图和对购买决策影响最大的职责。不要为了填满数量重复同一卖点、同一卡片布局或同一场景。

## 规划表

生成前在内部整理：

```text
图片编号：
职责：
购物者问题：
主要画面：
商品身份锁：
允许文案：
事实来源：
参考图及 role/preserve：
禁止内容：
输出尺寸和质量：
```

复杂文字优先规划无文字底图和后续确定性排版，不依赖图片模型准确生成长文、规格表或认证标识。

## 主图

准备 Amazon US 主图时同时读取 `amazon-us-guidance.md`。通常应使用真实商品参考图和 `preserve: "strict"`，强调纯白背景、单一商品主体、完整可见、无额外文字和装饰。

Skill 只提供生成与检查方向，不能声称图片已经通过 Amazon 审核或类目合规。

## 套图一致性

整套完成后检查：

- 商品几何、颜色、材质、Logo 位置和包装内容是否一致。
- 每张图是否承担不同职责，而不是同一构图的重复版本。
- 场景、人物和商品比例是否真实。
- 配色、光线和商业风格是否属于同一个系列。
- 所有具体卖点是否有可观察或用户确认的事实来源。
- 是否出现相互矛盾的规格、配件、功能或使用方式。

发现单张问题时优先基于该 asset 的明确版本进行 edit，不自动重跑整套。

## 第一阶段边界

本阶段只支持 Listing 图片规划和当前 AgentTool 可接受尺寸的独立图片生成。Amazon A+ 精确尺寸和确定性后处理不在本文件能力范围内。
