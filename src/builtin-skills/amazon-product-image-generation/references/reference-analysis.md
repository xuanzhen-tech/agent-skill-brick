# 参考图分析

仅当任务包含商品图、风格图、场景图、人物图或布局参考时读取本文件。分析结果用于构建提示词和 `referenceImages`，不是让模型复制参考作品。

## 输入清单

逐张记录 workspace 相对路径、主要角色、可以使用的事实和禁止迁移的内容。不要仅凭文件名推断图片内容。

参考角色与 AgentTool 参数对应如下：

|参考目的|role|常用 preserve|允许迁移|
|---|---|---|---|
|真实商品身份|`product`|`strict`|几何、颜色、材质外观、结构、包装和可见标识位置|
|真实 Logo|`logo`|`strict`|Logo 身份与位置意图；最终文字仍需人工检查|
|视觉风格|`style`|`loose`|镜头态度、光线、留白、材质氛围和信息密度|
|使用环境|`scene`|`loose` 或 `balanced`|环境类型、景深、照明和空间关系|
|版式结构|`layout`|`loose`|阅读顺序、主体占比、留白和信息区域关系|

不要从任何参考图复制原品牌、原商品、人物身份、价格、认证、促销、具体文案或未经用户确认的功能。

## 事实台账

将所有拟使用事实分类：

1. 可观察事实：图片中能明确确认的形状、颜色、结构和包装内容。
2. 用户确认事实：用户明确提供的规格、功能、配件、认证和性能。
3. 类别常见用途：只能用于保守场景描述，不能升级为性能承诺。
4. 不支持内容：无法观察且用户未确认的价格、评级、医疗效果、兼容性和比较结论。

提示词只能使用可观察事实和用户确认事实作为具体声明。不支持内容必须删除或追问。

## 风格契约

对最主要的风格参考输出四项短结论：

```text
必须保留：
允许适配：
禁止复制：
风格丢失风险：
```

至少检查这些维度：商业类型、镜头角度、主体与人物关系、留白、信息密度、排版节奏、情绪温度、材质和光线。

风格契约应描述视觉机制。例如“低机位近景、主体靠右、左侧大留白、硬质边缘光”，而不是只写“高级感”。

## 商品使用合理性

有人物或使用场景时，先判断：

- 真人通常如何握持、穿戴、打开、存放和操作该商品。
- 商品与手、身体、台面、地面或环境的比例是否可信。
- 参考动作是否适用于目标商品；不适用时只迁移镜头和情绪。
- 是否展示了未包含配件、危险动作或不可能效果。

无法确定合理使用方式时先询问，不要为了画面冲击力创造错误动作。

## 人物一致性

用户要求多张图复用同一人物时，建立人物身份锁：年龄范围、脸型、发型、肤色、体型和造型基调。每张图保持身份一致，但按职责调整姿势、表情、裁剪和相机角度。

服装、可穿戴商品或人物决定商品展示效果时，如果用户没有说明人物来源，应询问使用商品图人物、风格参考人物还是新生成人物。

## 输出给提示词

分析完成后只向提示词传入最小必要信息：

```text
商品身份锁：
风格契约：
使用合理性：
人物身份锁（如需要）：
禁止内容：
参考图顺序与 role/preserve：
```

不要把整份分析、参考图原文案或无关背景描述塞入生成 prompt。

## 设计来源

本方法吸收了用户提供的 MIT Skill“通用-视觉-电商图片生成引擎”中关于参考角色、风格迁移和使用合理性的思路，并按当前 AgentTool 合同重新组织；不沿用其 provider、固定产量或输出目录。
