# 补货执行准备上游方法

## 1. 两项强制上游

必须同时取得：

- Product 内置 `amazon-inventory-ledger-summary` 的正式输出；
- Product 内置 `amazon-operating-analysis` 的正式输出。

记录其文件/产物位置、版本、生成时间、站点、SKU/ASIN、库存节点、业务期间、单位、口径、责任方和限制。缺少任一整个产物时停止准备度判断。

产物存在但版本、字段定义或可追溯性无法理解时，也不能靠猜测继续；应说明不支持的具体部分和需要上游提供的定义。

## 2. 先映射，再比较

对当前任务所需的每个概念，写出上游真实字段或段落、原标签、定义、原值、单位、业务时间和它是事实、上游计算还是建议。

随后依次检查：

1. 对象：站点、SKU、ASIN、源/目标节点和变体是否相同。
2. 时间：库存时点、分析窗口和执行窗口是否仍适用。
3. 单位：件、箱、套等是否有可信转换。
4. 口径：可用、在途、预留、不可售、需求、候选数量等定义是否一致。

不可比时保留原值和差异，不强行合并。

## 3. 候选数量的合法来源

补货数量只能直接采用：

- 强制上游正式产物明确给出的候选数量；
- 用户在本任务中明确批准的数量；
- 其它可信正式产物中带版本、口径和责任人的数量。

本 Skill 不使用销量趋势生成、调整、优化或舍入候选数量，也不重新计算安全库存。

## 4. 可选三 MCP 外部需求情景

| 提供方与工具 | 可支持 | 不能支持 |
|---|---|---|
| SIF `ops_get_asin_sales_trend` | 外部销量趋势与季节性背景 | 一方订单、库存、候选数量或补货算法 |
| SellerSprite `asin_sales_trend` | 外部销量趋势情景 | 一方销量、在途或执行数量 |
| SellerSprite `asin_prediction` | 供应商预测情景 | 替换正式预测或计算补货量 |
| Sorftime `product_trend` | Amazon 商品趋势情景 | 一方销量、库存、采购或物流事实 |

多个来源只有对象、站点、期间、单位、粒度和定义可比时才并列；冲突不平均。计划来源缺失时说明覆盖限制，但不得用其补强制上游。

每次只保留提供方与精确工具、对象/范围/时间、原始值、直接用途、限制和原始结果位置。空结果、未返回或冲突不等于销量为零。

## 5. 执行准备度

逐候选核对：

- 两项强制上游存在且相互可对齐；
- 候选数量唯一、可追溯且单位明确；
- 源节点、目标节点和执行窗口明确；
- 库存/在途口径没有冲突；
- 人工批准人、批准范围和时间明确；
- 采购、调拨或 FBA 建件责任方已获得所需材料。

最终直接说明可交接、需满足条件后交接、暂缓，或因资料不足无法判断，并列出阻塞事实、最小补充材料和下一责任方。
