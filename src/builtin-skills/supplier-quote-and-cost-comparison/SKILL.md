# 供应商报价与成本比较

## 目标与完成定义

本 Skill 不以“最低单价”直接选供应商，而是回答：

1. 报价是否针对同一产品、版本、数量和交付范围；
2. 币种、单位、价格阶梯和有效期是否可比较；
3. 哪些费用已包含、排除、可选或未知；
4. 在明确数量情景下，报价范围内的总额和单位等价成本是多少；
5. 差异来自价格、MOQ、工具/模具、包装、付款、交期还是口径；
6. 哪些报价必须补充或重报价后才能进入决策。

结果可以是 `not_comparable`。保持不可比比用假设强行排出名次更可靠。

## 使用边界

### 合法输入

- 用户对话及只读 `uploads/` 中的报价单、邮件、聊天确认、价格表、样品费、模具费、包装费和条款；
- 可信上游 `outputs/` 中的采购规格、候选身份、数量情景和经批准的费用或汇率证据；
- 用户明确批准的同币转换规则、汇率来源、基准时点和适用范围；
- 合格责任方确认的 Incoterms、税费、测试或运输责任边界。

本 Skill 不调用三个 MCP。SIF/SellerSprite 市场价格、Sorftime/1688 挂牌价格和探索性采购上限都不能替代真实供应商报价、MOQ、币种、Incoterms、交期、付款、工厂条款、landed cost 或第14利润真相。

### 外部数据边界

- 不访问 `sif_mcp`、`sellersprite_mcp`、`sorftime_mcp`、Web、供应商平台、汇率 API、物流 API 或其他 MCP/API；
- 不向供应商自动询价，不读取邮箱或聊天账户；
- 不猜当前汇率、运费、关税、税率、保险或平台费；
- 合法输入不足时要求重报价或责任方补充，不静默换源。

### 工作区

- `uploads/` 只读；
- `temp/procurement/<case-id>/03-quote-comparison/` 存放报价抽取、单位转换、数量情景和可比性草稿；
- `outputs/procurement/<case-id>/03-quote-comparison/` 存放正式比较、差异账本和证据；
- 原始报价保留原版本与路径，归一表不得覆盖原文件。

### 证据与比较

每份原始报价保留：

- 报价 ID、供应商候选 ID、来源路径；
- 报价日期、版本、有效期；
- 产品/规格版本、币种、单位和数量阶梯；
- Incoterms 规则、版本、指定地点；
- 来源路径、提供者和限制。

每个标准化值、换算、总额、差异和可比性判断都要引用实际报价项，写明公式、输入值、单位、汇率日期、舍入和限制；不得只给最终排名。

## 启动检查

### 最低输入

至少需要：

1. 两份待比较报价，或同一供应商两个报价版本；
2. 可识别的供应商候选 ID；
3. 同一采购对象或可解释的规格差异；
4. 至少一个数量情景；
5. 报价币种、计价单位和日期；
6. 足以判断交付范围的条款。

只有口头“每件大约多少钱”时，可登记为线索，但不能形成正式排名。

### 启动判断

先判断核心采购对象、数量、单位、币种、交付范围和有效期是否一致。使用了可验证转换或明确调整时展示完整过程；只有部分费用/情景可比时只比较该部分。报价过期、内部或跨文件冲突、不可读或无法识别采购对象时，分别说明限制，不强行排名。抓取、代询价、谈判执行、下单和完整利润结论不在范围内。

## 执行流程

### 第一步：冻结报价版本

为每份报价创建 `quote_id`，记录：

- 文件、页码、消息或附件定位；
- 供应商候选及主体陈述；
- 报价日期、版本和有效期；
- 产品、规格、包装和质量版本；
- 报价人和接受人；
- 后续邮件或聊天是否构成正式修订。

不得把多个版本的最低字段拼成“最佳组合报价”。

### 第二步：抽取原始字段

原样保留：

- 币种、税务口径、计价单位；
- MOQ、数量阶梯、单价；
- 样品、模具、工装、包装、标签、测试、认证；
- 运输、保险、报关或其他费用；
- Incoterms 规则、版本、指定地点；
- 付款条件、交期、起算点和产能假设；
- 包含、排除、可选、未知项。

空白字段为 `missing`，不能自动解释为“免费”或“已包含”。

### 第三步：锁定比较情景

每个情景明确：

- 产品和规格版本；
- 数量与计量单位；
- 包装方式；
- 交付范围；
- 目标日期；
- 是否摊销一次性费用；
- 比较币种及合法汇率证据。

不同数量档、交付地点或规格不得放在同一排名列中。

### 第四步：执行可比性检查

逐项比较：

1. 采购对象是否等价；
2. 数量是否满足各自 MOQ 和阶梯；
3. 单位是否可由已证转换关系统一；
4. 币种是否相同或有批准的同一基准汇率；
5. Incoterms、版本和地点是否一致；
6. 包装、测试、模具和运输范围是否一致；
7. 报价是否仍有效；
8. 缺失项是否会改变排序。

任一关键项不可判断时，不得输出全局最低成本排名。

### 第五步：归一单位和币种

只允许：

- 使用产品/BOM 中明确的件、套、箱、千克等转换关系；
- 使用用户或可信上游提供的带来源、时点和报价方向的汇率；
- 记录原值、转换值、公式和舍入；
- 对无法转换的报价保留原币原单位。

不得调用实时汇率 API，也不得从记忆填入汇率。

### 第六步：计算报价范围成本

在每个数量情景中区分：

- `recurring_unit_cost`
- `quantity_tier_amount`
- `one_time_cost`
- `allocated_one_time_cost`
- `included_cost`
- `excluded_known_cost`
- `optional_cost`
- `unknown_cost`
- `quoted_scope_total`

`quoted_scope_total` 只代表报价明确范围。未知运输、关税、税费或平台费用存在时，不得命名为 landed cost、总成本或利润。

### 第七步：解释差异而非只排位

逐项给出：

- 原始差异；
- 归一后的可比较差异；
- MOQ/阶梯效应；
- 一次性费用摊销效应；
- 付款和现金占用差异；
- 交期和责任范围差异；
- 哪些差异仍是未知。

不使用固定权重综合分。用户确需权衡时，列出维度和决策门，由用户指定优先级。

### 第八步：生成补充与重报价清单

为每个不可比字段生成：

- 精确问题；
- 供应商需返回的字段；
- 单位、币种和格式；
- 是否需要修订版报价；
- 责任人和截止时间；
- 缺失时的决策后果。

本 Skill 不发送该清单。

### 第九步：转交利润判断

若用户问保本价、利润、到岸总成本或促销空间：

- 将报价范围成本、未知项和直接判断依据交第14专家；
- 不补造关税、物流、平台费、退货率或汇率；
- 保留“采购报价成本”和“完整经营成本”的边界。

## 失败与降级

- `missing_quote_fields`：仅输出字段缺口与重报价清单；
- `currency_not_convertible`：按原币并列，不排名；
- `unit_not_convertible`：保持原单位并标 `not_comparable`；
- `scope_mismatch`：拆分可比区块与不可比区块；
- `expired_quote`：只作历史证据，不作为当前选择依据；
- `conflicting_versions`：冻结各版本，要求确认有效版本；
- `unknown_cost`：不按零处理；
- 当任务要求抓取报价、外联、谈判、下单，或直接给出关税与利润定论时，当前 Agent 缺少外部执行权或相应专业输入，因而不能声称报价已获取、交易已推进或财务结论已成立；降级为可比口径、待补输入、谈判问题清单和需转交对应专家的事项。

## 正式交付

至少生成：

1. `supplier-quote-comparison.md`：范围、状态、情景、可比性、成本和差异；
2. `quote-normalization-ledger.csv`：原值、转换、公式、父证据和状态；
3. `quote-gap-and-requote-list.md`：缺失字段和重报价要求；
4. `quote-evidence-ledger.md`：原始报价、直接依据、换算过程和限制。

使用 `assets/templates/supplier-quote-comparison-template.md`。关键口径不可比时，报告标题和摘要必须明确 `not_comparable`，不得保留误导性排名。

## 质量门

- 报价版本、日期、有效期和供应商候选 ID 固定；
- 币种、单位、MOQ、阶梯和数量情景完整；
- Incoterms 含规则、版本和指定地点；
- 包含、排除、可选、未知严格分开；
- 空白和未知没有按零处理；
- 每个转换有来源、公式、单位和父证据；
- 没有把 quoted scope 称为 landed cost 或利润；
- 不可比时明确 `not_comparable`；
- 没有固定权重、抓价、自动询价或下单；
- 每项成本与比较判断均能回到报价原文，并写明计算、差异、限制和下一责任人。

- 写正式比较前读取或物化 `assets/templates/supplier-quote-comparison-template.md`。
