# 采购质量与交付计划

## 目标与完成定义

把“跟好质量和交期”转成责任明确、证据可追溯的执行计划：

1. 哪些特性是关键质量特性，如何验证；
2. 哪个样品或版本是批准基线；
3. 在何时、何地、由谁检查什么；
4. 规格、材料、工艺或包装变更如何申请和批准；
5. 偏差、不合格和 CAPA 如何记录、验证与关闭；
6. 交付里程碑、依赖、闸门和升级规则是什么。

计划完成不等于检查、生产、出货或 CAPA 已经完成。只有用户或合格责任方提供执行证据时，状态才可更新。

## 运行合同

### 合法输入

- 用户对话及只读 `uploads/` 中的规格、图纸、BOM、质量协议、包装标准、样品记录、测试要求、交期和合同附件；
- 可信上游 `outputs/` 中的寻源要求、供应商评估、报价、合规限制和已批准决策；
- 用户或合格质量责任方提供的 AQL、抽样方案、测试方法、阈值、检查报告、偏差批准和 CAPA 证据；
- 供应商提供的生产计划、样品、材料、工艺和交期陈述，保留为 `reported`。

### 外部数据边界

- 不使用 SIF 获取供应商身份、生产、材料、产能、样品、质量、MOQ、报价、交期或交付事实；其 ASIN 画像与探索性采购上限不适用于本 Skill；
- 不调用 Web、1688、ERP、QMS、WMS、邮件、聊天或其他 MCP/API；
- 不自动催单、发通知、排日程或创建后台监控；
- 不猜 AQL、抽样量、测试标准、合规阈值或生产周期；
- 输入不足时输出数据准备和责任方确认清单。

### 工作区

- `uploads/` 只读；
- `temp/procurement/<case-id>/04-quality-delivery/` 存放 CTQ 映射、检查计划、里程碑和异常草稿；
- `outputs/procurement/<case-id>/04-quality-delivery/` 存放正式计划、登记表和证据账本；
- 执行证据作为新版本追加，不覆盖历史基线。

### 双层证据谱系

输入证据记录产品/规格版本、来源路径、提供者、日期、有效范围、四轴和限制。

Agent 产生的 CTQ 分类、检查点、里程碑依赖、风险、升级和草拟验收规则是 `agent_output`，必须引用父证据。没有合格来源的数值阈值标为 `tbd_by_qualified_owner`，不得由 Agent 自定。

## 启动检查

### 最低输入

至少需要：

1. 产品或部件及规格版本；
2. 当前采购阶段；
3. 已知关键功能、材料、尺寸或包装要求；
4. 目标数量与交付节点；
5. 质量、采购和技术责任方；
6. 对样品、检查或批准的现有要求。

若没有可验证规格，只能先生成质量数据准备清单，不得用通用检查表冒充产品计划。

### 计划状态

- `ready_for_approval`：控制对象、标准、责任人和闸门完整；
- `conditional`：允许推进，但部分标准等待责任方确认；
- `missing_quality_basis`：CTQ 或验收依据不足；
- `schedule_conflict`：里程碑、交期或依赖冲突；
- `change_unresolved`：未批准变更影响基线；
- `blocked`：无法识别产品版本或决策责任方；
- `out_of_scope`：实际验货、催单、QMS 操作、供应商承诺或自动监控。

## 执行流程

### 第一步：冻结质量基线

记录：

- 产品、部件、BOM、图纸和包装版本；
- 适用市场和数量批次；
- 批准状态、批准人和日期；
- 关联样品或金样；
- 当前未批准变更。

不同版本不得共用一套验收结果。

### 第二步：建立 CTQ 清单

从产品功能和风险出发，把要求分类为：

- 安全与法规关键；
- 功能与性能关键；
- 装配与互换关键；
- 材料与耐久关键；
- 外观和品牌关键；
- 包装、标签和运输关键。

每条 CTQ 记录规格值、单位、公差、测试/检查方法、样本阶段、判定责任人和证据。空泛的“做工好”必须转成可观察标准或标记缺口。

### 第三步：管理样品与金样

分别记录：

- 样品 ID、版本、来源和日期；
- 打样目的；
- 与规格的偏差；
- 测试结果和证据；
- `approved`、`approved_with_deviation`、`rejected` 或 `pending`；
- 批准人和适用范围；
- 是否成为 golden sample；
- 金样保管、照片/文件定位和失效条件。

Agent 不能自行宣布样品批准或金样成立。

### 第四步：设计检查与控制节点

按业务需要设置：

- 物料/首件确认；
- 生产前评审；
- 过程中检查；
- 完工检查；
- 装箱/标签检查；
- 出货前放行；
- 到货抽检或问题反馈。

每个节点说明对象、时间、地点、责任方、方法、输入、输出、通过条件和阻塞动作。节点类型按实际需要选择，不强制所有项目都使用全部节点。

### 第五步：引用抽样和验收方案

AQL、抽样量、缺陷分类和接收数只能：

- 由用户提供；
- 来自合同或质量协议；
- 由合格质量责任方确认；
- 作为带版本、日期和适用范围的上游证据。

缺失时写 `tbd_by_qualified_owner`。不得使用“行业一般 AQL 2.5”等固定默认。

### 第六步：建立变更控制

任何材料、供应商、工艺、模具、尺寸、颜色、包装、标签或生产地点变化都记录：

- `change_request_id`
- 原基线与拟变更；
- 变更原因；
- 受影响 CTQ、样品、测试、成本和里程碑；
- 所需再验证；
- 批准人；
- `proposed`、`under_review`、`approved`、`rejected`、`implemented`、`verified`。

未批准变更不得写入正式基线。

### 第七步：设计偏差与不合格处理

对实际执行证据中的偏差记录：

- 批次、对象和观察；
- 规格/CTQ 引用；
- 数量和范围；
- 临时隔离或处置建议；
- 根因状态；
- 责任人和截止时间；
- 决策：返工、返修、让步接收、退回、报废或待定；
- 人工批准和验证证据。

Agent 只能形成建议和记录，不能执行处置。

### 第八步：建立 CAPA 闭环

CAPA 至少区分：

1. 遏制：控制当前影响；
2. 根因：已证根因或待验证假设；
3. 纠正：处理已发生问题；
4. 预防：改变系统以降低复发；
5. 验证：如何证明措施有效；
6. 关闭：由谁基于什么证据批准。

“已回复”“已培训”或“供应商承诺”不自动等于 CAPA 有效。

### 第九步：构建交付里程碑

为每个里程碑记录：

- 计划与承诺日期；
- 时区和日期定义；
- 前置依赖；
- 所需批准或证据；
- 责任人；
- 状态来源和更新时间；
- 延误影响；
- 升级触发器。

供应商陈述的日期标为 `reported`，不得写成 Agent 已实时确认。

### 第十步：执行 go/no-go 审阅

在打样、量产、出货等闸门检查：

- 基线是否批准；
- 关键 CTQ 是否有方法和阈值；
- 样品/金样是否有效；
- 必要检查是否有计划或结果；
- 变更、偏差和 CAPA 是否阻塞；
- 交付依赖和批准是否完整。

结论只能是 `go`、`conditional_go`、`hold` 或 `not_assessable`，并记录人工批准。

## 失败与降级

- `missing_specification`：只输出质量资料缺口；
- `missing_sampling_plan`：保留检查节点，抽样字段标 `tbd_by_qualified_owner`；
- `unapproved_sample`：不得称金样或量产基线；
- `unapproved_change`：保持原基线，状态 `hold`；
- `supplier_status_unverified`：标 `reported`，不写已完成；
- `schedule_conflict`：列出冲突和责任人，不自动改期；
- `partial_result`：交付可计划区块与阻塞区块；
- `out_of_scope`：实际验货、催单、系统操作、消息发送或自动监控。

## 正式交付

至少生成：

1. `procurement-quality-delivery-plan.md`；
2. `ctq-and-inspection-register.csv`；
3. `sample-change-deviation-capa-register.md`；
4. `milestone-and-gate-register.csv`；
5. `quality-delivery-evidence-ledger.md`。

使用 `assets/templates/procurement-quality-delivery-plan-template.md`。没有执行证据时，状态保持 `planned` 或 `pending`，不得填写 completed。

## 质量门

- 产品、规格、样品和批次版本清楚；
- CTQ 有值/单位/方法或明确责任方缺口；
- AQL、抽样和阈值没有由 Agent 硬编码；
- 金样有批准人、范围和失效条件；
- 变更未获批前没有改写基线；
- 偏差、CAPA 和关闭证据分开；
- 供应商日期与执行状态保留 `reported`；
- 没有声称已验货、催单或操作系统；
- go/no-go 有证据、条件和人工责任人；
- 双层谱系与工作区边界完整。
