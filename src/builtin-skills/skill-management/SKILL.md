# Skill 使用与管理

## 目标

Skill 是可安装、可选择、按需加载的能力包：正文规定工作方法，references 提供资料，scripts 提供执行辅助，assets/templates 提供资源。安装 Skill 不会自动赋予工具权限、连接器凭据或网络权限；缺少依赖时必须如实说明。

产品同时支持两类能力：官方维护的预置能力，以及用户自行管理的非预置能力。官方内容持续更新，用户保留是否使用它的决定；用户要长期定制，应建立独立名字的能力，而不是依赖对预置包的本地修改。

先完成用户任务，再决定是否需要安装或沉淀能力。不要把一次任务擅自扩大为创建 Skill，也不要把产品预置范围误认为用户唯一可安装的范围。

## 运行合同

### 六个不同的概念

- **产品预置集合**：当前 Agent 由 Product 指定、启动时接受官方维护的名称集合；不是用户启用名单，也不是 SDK 的全部目录。
- **已安装**：受管文件与安装登记存在。仅在磁盘放一个同名文件夹，不等于已通过安装、登记或启用。
- **用户期望启用**：Product 持久保存的用户选择。停用不会移除文件；同步不会自行把已有停用项启用。
- **当前可用**：已安装、已选择、校验健康且本次未被隔离的部分；保存为启用但内容不可用的项，不能说成可调用。
- **激活**：通过 skill_activate 把完整正文加载进当前对话；不是持久启用，也不是安装。
- **删除**：通过受控接口移除非预置包及其登记和选择；与停用不同。

### 渐进式加载

1. 当前可用 Skill 的 name 和 description 以摘要形式进入上下文。
2. skill_find 返回发现结果和远端候选，不返回完整正文；搜索结果不一定覆盖所有停用库存，远端同名候选也不证明本地存在。
3. 任务匹配后，通过 skill_activate 加载完整 SKILL.md；CLI 将正文提升为 loaded_skill 上下文。
4. references、workflows、assets 和 templates 按需经 skill_resource 访问，不一次加载全部资料。
5. 同一对话已激活的正文由 CLI 按内容 hash 去重和保留。启停或修改后，不要承诺历史消息和已经加载进旧对话的文本被抹除；通过下一轮运行的权威状态验证，必要时使用新对话验证新内容。
6. scripts 不因安装或激活自动执行；任务需要且现有工具允许时才能运行。

### 受管路径与 Agent 范围

下面使用占位符表示完整路径，不写入某台电脑的盘符或用户名：

- `<用户主目录>`：当前运行用户的 Home 目录，由当前环境提供；不是桌面、任务工作目录或项目仓库。
- `<产品目录名>`：宿主当前产品身份中的 `appId`，对应用户主目录下的产品目录名。使用当前宿主提供的值，不在本文固定名称。
- `<expertId>`：当前专家／通用代理的真实 Agent 标识。
- `<skill-name>`：目标 Skill 的精确 canonical name。

| 内容 | 路径模板 |
|---|---|
| 客户助理 Skill 根 | `<用户主目录>/<产品目录名>/.agent-cli/skills/` |
| 专家／通用代理 Skill 根 | `<用户主目录>/<产品目录名>/.agent-cli/operations-experts/<expertId>/skills/` |
| 客户助理的一个包正文 | `<用户主目录>/<产品目录名>/.agent-cli/skills/<skill-name>/SKILL.md` |
| 专家／通用代理的一个包正文 | `<用户主目录>/<产品目录名>/.agent-cli/operations-experts/<expertId>/skills/<skill-name>/SKILL.md` |
| 客户助理启用选择 | `<用户主目录>/<产品目录名>/.agent-cli/product/skill-selection.json` |
| 客户助理交付记录 | `<用户主目录>/<产品目录名>/.agent-cli/product/skill-delivery.json` |
| 专家启用选择 | `<用户主目录>/<产品目录名>/.agent-cli/operations-experts/<expertId>/product/skill-selection.json` |
| 专家交付记录 | `<用户主目录>/<产品目录名>/.agent-cli/operations-experts/<expertId>/product/skill-delivery.json` |

参考资料、脚本和资源位于对应包正文同级的 `references/`、`scripts/`、`assets/`、`templates/` 中；资源工具使用包内相对路径。

这些模板描述默认目录布局。先从当前环境取得用户 Home，再从宿主上下文取得产品目录名和当前 Agent 标识，代入占位符；不能把占位符原样传给工具。若安装结果已经返回目标包路径，直接使用该结果，无需重新推算。宿主显式配置数据位置时，实际注入的 `config.skillsPath` 或安装结果中的 `managedRoot`、`path`、`managedSkillsPath` 优先于默认模板，并按字段含义区分根目录与具体包路径。

没有足够信息确定某个占位符时，应说明缺少哪项宿主信息，不从其他电脑的路径猜测。通过 Skill 名称和包内相对路径即可使用的工具，不需要自行拼接文件系统路径。路径模板用于理解和定位，不授予直接修改受管包或状态文件的权限；不得把解析出的本机路径固化进可分发的 Skill。

客户助理、通用代理、各专业专家的包、选择和交付记录独立。同名不代表同一份文件；在一个 Agent 安装、修改、启停或删除，不代表其他 Agent 也完成了。当前“规则公式 → 系统能力”页面展示客户助理库存，不因用户从某个专家页面打开它就变成该专家的管理页。

上述状态文件仅用于理解职责与解释位置。不得直接修改 selection、delivery、旧 skill-initialization.json 或 SDK 私有登记；不得通过 shell 删除／复制受管目录、修改环境变量或更改产品预置配置来绕过公开接口。旧初始化文件不是阻止后续官方同步的总开关。

### 工具与产品入口

| 入口 | 作用及边界 |
|---|---|
| skill_find | 搜索与安装指定候选；区分本地结果和远端候选，遵循实际 schema |
| skill_activate | 加载正文及资源清单，不改变持久启停选择 |
| skill_resource | read_reference 读取资料，copy_asset 将资源复制到 workspace 的受控位置 |
| skill_create | 通过 SDK 安装完整新包或替换同名包；默认先检查冲突 |
| skill_remove | 用户明确要求后删除当前 Agent 的非预置包；按实际 schema 传精确名称及 confirm，不接受路径 |
| 系统能力页面 | 客户助理库存、来源、预置标识、启停与允许的删除；预置仅显示启停 |
| Product 公开库存与启停接口 | GET `/api/agent/skills` 返回客户助理库存，含 removable/enabled；PATCH `/api/agent/skills/enabled` 接受 `{skillName, enabled}`，由 Product 完成选择事务 |

API 路径用于说明产品合同，不表示模型自动拥有 HTTP 操作能力。以当前开放工具和宿主授权为准，不猜服务端口，不用 shell/curl 临时绕出一套管理入口。当前 Skill 工具组没有独立的持久启停工具；如当前没有可用的受支持入口，指导用户在对应管理界面启停，并明确“尚未代为执行”。不要伪造 skill_enable/skill_disable，也不要用 activate 代替 enable。

## 产品管理策略

### 识别预置身份

预置身份取决于当前 Agent 的 Product 预置集合。权威库存的 `removable=false` 对应受保护预置项；`removable=true` 对应允许删除项。界面来源标签、包名相似、SDK 官方目录存在、用户从跨境生态下载，都不能单独决定保护身份。

不同 Agent 可以有不同的预置集合，集合也会随产品演进变化。本文不维护具体名称或数量；执行前读取当前 Agent 的权威库存与保护标识。新增、改名或移出预置范围后，按当前产品配置判断，不沿用历史名单。

若当前工具未提供 removable 或完整库存，承认信息不足；使用已有公开宿主入口或让用户查看预置标识。不要凭 skill_find 没有返回某项就断言未安装，更不要用尝试删除的方式探测其身份。

### 官方内容每次启动覆盖，选择独立保留

1. 每次 Product 启动并初始化对应 Agent 的 Skill Runtime 时，同步该 Agent 当前全部预置包；不是只在首次安装客户端或升级版本时执行，也不是每次发消息执行。
2. 权威内容来自已集成 SDK 的官方来源。各预置包由产品装配所指定的 SDK 公开安装入口提供完整内容；不按本文中的名称列表选择来源。Product 不另行直连服务器，也不由 Agent 手工下载。
3. 使用 SDK replace 语义重覆盖完整包，包括正文、资源和包内附加内容；无需判断 hash 差异来自官方更新还是本地修改，不做 Git 式合并，不保留预置包中的本地差异。
4. 不论启用还是停用，预置包内容都参与同步。已有用户启停选择保持不变。官方同步不是用户手动 reinstall，也不意味着自动重新启用。
5. 新增、此前未交付的预置项同步成功后默认启用；逐 Skill 交付记录只决定这一默认选择，不再决定已有包是否同步。
6. 预置包本地被删除，下次启动会补回；本地被改写，下次启动会恢复 SDK 内容。曾安装后删除与从未交付仍有不同的历史事实，但现在两者都要补齐官方内容，不能拿“非全新”跳过同步。
7. 所谓“最新”是此次 SDK 官方同步成功取得并确认的内容，不保证超出 SDK 能力获得未发布内容；失败不能宣称已更新。
8. 同步失败的预置项保留诊断，本进程不作为健康可用能力暴露，下次启动重试。停用项也需要同步；不得通过强行启用旧包绕过失败隔离。一般单项失败不阻止其他健康能力；选择状态损坏或事务一致性故障不能冒充普通单项失败或新用户初始化。

### 用户自主管理非预置包

- 非预置包可以来自跨境生态、其他可支持远端、本地导入或 Agent 创建；不要求它们进入产品预置集合才能使用。
- 非预置包不会被该启动策略自动重覆盖，也不会因用户通过正式删除入口删除而自动恢复。用户指定更新时再走 SDK 受控替换。
- 新安装／创建成功经 Product 选择代理加入当前 Agent 的选择；仍须验证最终启用和健康状态。主动替换同名包属于安装操作，不能套用“启动同步保留停用”的结论，应核对最终启停结果。
- 自定义包也必须满足 SDK 校验、安装登记和产品选择条件；“不自动覆盖”不等于无需校验，缺失或损坏也不等于可以调用。
- 一旦某名字在未来版本进入当前 Agent 的预置集合，它就受官方维护规则约束；不要给用户承诺自定义名字永久豁免。为定制副本选清晰、不同于现有预置项的名字。

### 启停与删除

- 停用：从当前启用选择中移出，保留包及登记，之后可以重新启用。预置项停用后仍同步官方内容。
- 启用：选择已安装且健康的包；失败需说明原因，不把“保存期望”说成实际可用。
- 预置删除：页面不提供；Agent 工具和 HTTP 下层也拦截。返回“预置 Skill 不支持删除，请停用；启动时将同步 SDK 官方内容。”不能说“删除成功但重启恢复”。拒绝时不改变文件和启停状态。
- 非预置删除：成功后清理当前 Agent 的受管包、安装登记、索引和选择，生态安装登记按同一所有权链路清理。外部导入源文件、原始压缩包、其他 Agent 的副本、已有对话及历史不因该操作被删除。
- 删除失败：按实际失败报告并检查权威状态，不说成功，不转而用 shell 强删。

## 场景与用户提醒

提醒必须在有影响的写操作之前，具体说明目标、范围和后果；用户已明确授权且已了解后果时不要重复询问。普通使用和已经明确的启停不需要每次宣读整套策略。

| 用户指令／场景 | Agent 应如何处理及说明 |
|---|---|
| “用这个 Skill 做任务” | 判断已启用可用后激活；说明缺少的工具或依赖，不擅自更新或创建 |
| “这个功能不要用了” | 区分停用与删除；预置建议停用，非预置按用户是否要保留恢复能力选择 |
| “删除预置 X” | 告知只能停用；不调用删除来尝试，不改名单文件规避；若无启停工具指导用户操作，不能假称已停用 |
| “修改预置 X，长期按我的规则工作” | 先解释下次启动覆盖；建议不同名完整副本，验证可用后停用原项，协商用户想要的名称与触发范围 |
| “官方和我都改了同一个预置 X” | 说明启动以 SDK 为准，不合并；若用户改动尚在且希望保留，先经受支持资源访问及创建流程保存到不同名包；已被覆盖且无备份时不能声称可以恢复 |
| “我知道重启会还原，只临时改 X” | 确认用户已了解后果，再经受支持的冲突检查／替换流程执行；报告是临时修改，不能承诺持久保存 |
| “更新我自己建的 X” | 核对非预置身份和精确名字，检查同名冲突；获得覆盖授权后替换完整包，验证资源和启用状态 |
| “删除我下载的 X” | 核对其非预置身份，说明删除受管副本及选择、保留外部源包与历史；已有明确删除授权即可执行 |
| “停用了，为什么重启文件还是变了” | 解释停用控制是否使用，官方维护控制内容；两者独立，无需用户启用才能同步 |
| “新增能力为什么没看到” | 区分 Agent 范围、安装、停用、同步失败与正文激活；不直接清空状态重新初始化 |
| “帮所有专家都改好” | 明确各 Agent 独立，当前工具只作用当前实例；逐范围使用真正存在的入口，没有能力时说明未完成部分 |

推荐的预置定制提醒：

> 这是产品预置 Skill，启动时会用 SDK 官方包覆盖。直接改它只能临时生效。要长期保留你的规则，建议创建不同名的完整副本，并在副本验证通过后停用原项；副本后续不会自动继承原项的官方更新。

推荐的删除提醒：

> 这个非预置 Skill 可以删除。删除的是当前 Agent 安装的副本、登记和启用选择，外部导入源包及历史对话会保留；再次使用需要重新安装。

## 工作流

### 第一步：核实目标和当前事实

1. 判断用户要使用、启停、安装、修改、复制还是删除；一次任务不等于授权沉淀新能力。
2. 核对当前 Agent、精确名称、是否预置、安装和启用状态。已有公开信息足够时直接使用；不足时说明缺口，不编造状态。
3. 对预置修改、永久删除、同名覆盖或跨 Agent 操作，按上方场景说明后果；用户未明确选择的关键分支再协商。

### 第二步：发现和安装

1. 当前摘要有匹配且可用的项，直接激活；否则用 `skill_find({ action: "search", query })` 搜索，按需限定来源。
2. 区分本地结果与远端候选，根据名称、描述、来源和精确标识确认对象；不能仅凭相似名称替代。
3. 用户要求安装后调用 `skill_find({ action: "install", ...候选精确标识 })`。skills.sh 候选用 package，SkillHub/ClawHub 用 slug，受控 GitHub 用 url 和 name；具体字段以当前 schema 为准。
4. 本地导入通过产品原生选择器选完整包根目录的 SKILL.md，由 SDK 复制完整包。Agent 不使用 shell 将包塞入受管目录。
5. 分别报告安装结果、启用状态及可调用性；遇到 diagnostics 先说明，不把安装成功等同于所有功能可执行。

### 第三步：激活和使用

1. `skill_activate({ skill: "<精确名称>" })` 加载正文；不只凭摘要执行复杂流程。
2. references 用 `skill_resource({ action: "read_reference", skill, path })` 按需读取；assets 用 copy_asset 复制，使用返回的真实路径。
3. 停用项不要靠 activate 试图绕过选择限制；没有可用启停工具时明确交由用户或宿主操作。
4. Skill 要求的工具不可用时说明能力边界，不虚构工具，不仅因为 Skill 提到脚本就自动执行。

### 第四步：创建、定制或更新

1. 明确任务边界、触发表达、成功标准；description 同时说明做什么和什么时候使用。
2. 正文放关键机制与流程，长资料放 references，脚本放 scripts，模板／二进制放 assets；必要资源必须随完整包交付。
3. 先核实原项是否预置。长期定制预置项时选不同 canonical name，副本名称应与原项及已有安装项不同，并清楚表达定制用途；同步修改 frontmatter.name、文内自引用及相关资源引用。只改显示标题不能改变受保护身份。
4. 读取原正文和任务所需资源，用公开工具重建完整包。不能假定仅复制 SKILL.md 就复制了脚本和模板；当前工具无法取得或封装某资源时说明缺口，不用 shell 读取／复制受管目录绕过边界，不把残缺副本说成完整。
5. 第一次用 skill_create 的 conflict=check。conflict 表示未覆盖；只有明确授权覆盖现有同名包后使用 replace。用户授权“基于 X 定制”不等于授权覆盖另一个已有的同名自定义包。
6. 通过 find、activate、按需 resource 和代表性任务验证新包；成功后再按已确认方案停用原预置项。副本创建失败不先停用可工作的原项。
7. 副本与原包独立，停用原项不会停止其官方同步，副本也不会自动得到官方后续改进。后续用户需要吸收改进时，另行读取新版内容并受控更新副本，不承诺自动合并。
8. 用户明确只要临时修改预置项且接受重启还原时，可经 skill_create 检查和授权替换；最终说明临时性及当前启用状态，不把本次成功冒充官方版本已更新。

### 第五步：删除和验证

1. 仅处理用户明确要求删除的精确非预置名称。预置项转为停用说明，不修改产品预置集合。
2. 按 schema 使用 `skill_remove({ skill: "<精确名称>", confirm: true, reason: "用户明确要求删除" })`；不传文件路径。
3. 若停用包未出现在工具索引中而工具不能删除，使用允许的管理界面／宿主入口，不声称该包不存在，不擅自启用后再删除。
4. 成功后通过当前公开库存确认移除；find 核验时区分远端候选，不把远端仍可搜索误判为删除失败。不能单凭未出现在启用摘要就证明磁盘已删除。
5. 报告实际作用的 Agent、名称和结果，指出仍未完成的范围。不要把其他 Agent 的同名包算进本次删除。

## 失败与降级

- 预置保护拒绝：说明可停用，不重试删除、不改状态文件。
- 官方同步失败：说明该项本次不可用与下次启动重试；不得保证重启必定修复，不绕开 SDK 拉取或启用旧内容。
- 安装失败或同名冲突：保留精确候选和错误，按用户授权处理冲突；不转用 shell 下载受管包。
- 已安装但不可见：区分停用、未登记、不健康、同步失败和 Agent 范围。用户期望启用不等于实际可用。
- 状态文件损坏或一致性故障：报告产品状态问题，不删除文件当作首次安装，不把重建用户选择当作无害修复。
- 激活失败或资源不存在：核对名字、索引与资源清单；不猜受管绝对路径读取内容。
- 工具未开放：只使用实际可用能力，指导受支持的产品入口。skill_create/skill_remove 的缺失不能用 shell 替代。
- 用户修改已被官方覆盖：说明恢复需要实际存在的备份或对话材料；不能声称 SDK 保留了可恢复的历史副本。
- 操作结果不明确：先读权威状态再决定是否重试；不能凭按钮变化或文件名存在宣称事务成功。

## 质量门

完成 Skill 任务前确认：

- 当前 Agent 和精确 Skill 名称已核实；预置身份不靠来源标签或 SDK 目录猜测。
- 安装、启用、激活、当前可用和删除的含义没有混淆。
- 预置修改的重启覆盖后果、长期副本方案以及原项停用计划已按任务需要告知用户。
- 长期定制副本使用不同 canonical name，必要资源完整，未承诺自动跟随官方更新。
- 当前执行入口确实开放；未伪造启停工具或把尚需用户操作的步骤说成已完成。
- 安装、替换和删除经 SDK／Product 公共合同执行，没有直接写受管包、选择文件或 SDK 登记。
- conflict、unchanged、installed、replaced 和失败有明确区分，关键状态经公开结果核验。
- 不把凭据、token、密码写入 Skill；共享内容不绑定某一用户的私人路径。正文使用从用户主目录起算的占位符路径模板，运行时按本机与宿主信息解析，不写入任何特定设备的真实绝对路径。
- 说明实际验证范围；历史对话、新轮次状态和下一次启动效果分别陈述，未执行的启动验证不冒充完成。
