# 竞品基线比较合同

## 基线最小身份

每个基线快照至少包含创建时间、Amazon 站点、币种、ASIN/父子体范围、来源或供应商精确工具、数据截至时间与期间、筛选条件、字段原值、原始位置和限制。缺少站点、实体、字段语义、数据期间或数值形成方式时，基线不能用于数值比较，只能作为不可比的历史材料引用。

## 字段可比闸门

只有同时满足以下条件，字段才可比较：

1. Amazon 站点一致；
2. ASIN 身份和父子体口径一致；
3. 字段业务语义一致；
4. 单位、币种和百分比尺度一致；
5. 都是同一来源工具，或已证明跨工具口径等价；
6. 两侧都说明数据期间、是来源报告/估算还是 Agent 计算，以及换算规则；
7. 数据期间和时间粒度足以支持本次陈述；
8. 上游证据保留来源文件、版本、原值位置和原有限制，没有伪装成本次 MCP 数据。

任一条件不满足，明确写“不可比较”，保留两侧原值但不计算差值。来源报告与供应商估算、原始值与 Agent 计算不要求机械相同，但差异必须可解释且不改变指标语义；供应商报告值不等于 Amazon 一方观测。

## 比较输出

每个字段输出 ASIN/父子体范围、字段、基线与当前来源、原值、单位、期间、绝对差值、相对差值、是否可比、业务解释和替代解释。新增字段要说明可能只是 schema 扩展；缺失字段不得推断为商品删除。

## 数据形成方式的比较

- 同一供应商或文件不自动证明同口径；跨来源只有在字段定义和采集方法已证明等价时才可比较。
- 当前快照按各自截至时间比较；历史序列按相同期间和粒度比较；未来预测不得冒充当前或历史结果。
- 来源报告值与供应商估算/预测不得无说明互换；两个估算值只有在估算定义和版本可比时才比较。
- Agent 规范化或计算必须使用同一公式与输入尺度，并说明直接依据；编码、推断和假设默认不做数值差值。

## 计算规则

- 数值可比时：`absolute_delta = current - baseline`。
- 基线非零且单位一致时：`relative_delta = absolute_delta / baseline`。
- 基线为零时不输出相对变化率，写 `not_applicable`。
- 比率先确认原始尺度是 `0–1` 还是 `0–100`，标准化后保留原值。
- BSR 是名次型指标；只在同类目同口径下解释数值变小为排名更靠前、数值变大为更靠后。
- 文本字段只输出新增、删除或改变的显式片段；不计算伪精确的“质量提升率”。
- 布尔标志只输出 `false → true`、`true → false` 或不变，不推测业务效果。

## 时间表述

| 证据数量 | 允许表述 | 禁止表述 |
|---:|---|---|
| 1 | 当前快照、首次基线 | 上升、下降、趋势、改善、恶化 |
| 2 | 相对基线增加/减少、本次变化 | 长期趋势、持续增长、稳定下滑 |
| 3 个以上同口径时点 | 描述序列方向与异常点 | 未经统计支持的季节性或因果 |

即使有三个以上时点，也必须披露缺口和不等间隔；本 Skill 不自动执行趋势模型。

## 首次运行

没有合格基线时：

1. 生成当前快照；
2. 把本次快照命名并记录版本；
3. 明确说明“本次仅建立首次基线”；
4. 比较表保留为空并说明原因；
5. 列出未来手动复核所需的同站点、同 ASIN、同字段条件；
6. 不创建定时任务或提醒。

## 冲突与缺失

- 基线比当前字段丰富：当前缺失字段标 `missing`，不推断已删除。
- 当前比基线字段丰富：写明“当前新增返回字段”，但可能只是 schema 扩展，不能直接称商品新增。
- 工具 schema 变化：优先写“不可比较”，并记录前后字段定义。
- 数据期间不同：只有业务语义允许时比较，并在解释中显式写期间差异。
- 任一侧缺少数据期间、数值性质或换算规则：写“不可比较”，不从字段名猜测。
- 多份基线冲突：不自动选最有利的一份；按来源、口径和时间排序，要求用户选择或将分支标为 `blocked`。
