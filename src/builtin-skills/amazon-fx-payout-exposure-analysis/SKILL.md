# Amazon FX 与回款暴露分析

## 目标

回答：

- 平台结算、支付渠道和银行到账是否属于同一笔交易；
- 每一步用什么币种、金额和汇率；
- 参考率、报价率、结算有效率和到账有效率分别是什么；
- 汇差、显式费用、其他扣款和未解释差额各有多少；
- 两个渠道或时期是否真正可比；
- 未来汇率变化会怎样影响现金，但不预测市场。

## 开始条件

至少需要：

- 交易或 payout 标识（掩码）；
- 平台应结算金额、币种和时间；
- 渠道实际换汇/结算金额、币种和时间；
- 银行实际到账金额、币种和时间；
- 显式费用、税费或其他扣款；
- 参考汇率材料（若要比较）及时间、方向；
- 汇率报价方向和金额是 gross 还是 net；
- 人工审核人。

金额、币种、时间或交易联接不清时，不计算有效汇率。

`uploads/` 只读；过程材料写入 `temp/profit-management/<run-id>/01-fx-payout/`，正式结果写入 `outputs/profit-management/<run-id>/01-fx-payout/`。

## 执行流程

### 1. 冻结同一交易链

把以下环节串起来：

`Amazon 应结算 → 渠道接收 → 换汇/结算 → 银行到账`

核对 payout、批次、金额、币种、日期、渠道和银行记录。多个 payout 合并到账或一笔 payout 分批到账时，必须有可解释分配；否则只做部分链分析。

### 2. 统一报价方向

明确汇率表示：

- `1 单位源币 = x 单位目标币`，还是反向；
- 分子和分母金额；
- 使用 gross 还是扣费后 net；
- 汇率时间是报价、成交、结算还是到账；
- 是否含费。

需要反转时：`反向汇率 = 1 / 原汇率`。不要在方向不明时凭数值大小猜。

### 3. 区分四类汇率

- **参考中间价**：某时点市场参考，不代表可成交；
- **渠道报价率**：渠道显示的报价，可能有期限和条件；
- **结算有效率**：`目标币结算金额 ÷ 源币结算金额`；
- **银行到账有效率**：`目标币实际到账 ÷ 源币原始金额`。

它们的金额基础、时间和费用不同，不能混用。

### 4. 检查可比性

比较两个渠道/时期前对齐币对和方向、原始金额、gross/net、费用范围、报价/结算/到账时间、结算速度、税费/提现条件及交易链。

完全可比才比较精确汇率；部分可比只给方向；不可比则分开展示。

### 5. 拆分差额

以同一原始金额为基础，分别估计：

- 参考率与实际率造成的汇差；
- 显式渠道费；
- 银行费；
- 税费或其他扣款；
- 四舍五入；
- 仍无法解释的差额。

核对：

`预期到账 - 实际到账 = 汇率影响 + 显式费用 + 其他扣款 + 未解释差额`

每一项说明公式和直接材料。不能为了闭合等式把未知自动塞进“费用”。

### 6. 构造未来情景

情景不是预测。用用户批准的汇率或变动区间计算：

`情景目标币金额 = 暴露源币金额 × 情景汇率 - 已知费用`

展示基准、升值/贬值方向、金额影响和假设。不推荐具体交易时点或渠道。

### 7. 给出行动含义

可建议补齐费用/结算记录、核对 gross/net、改善 payout 与银行记录匹配、统一预算参考时点或设人工复核阈值。不执行换汇、划款或监控。

## 三 MCP 边界

`sif_mcp`、`sellersprite_mcp`、`sorftime_mcp` 均不提供结算、汇率、payout、银行到账或现金流真相，本 Skill 不调用它们。三家关键词、ASIN、销量、广告、价格或采购数据不得进入交易链和汇率计算。

## 失败与降级

- 无法联接同一交易：分别展示，不计算链条差额；
- 报价方向或币对不明：不转换；
- gross/net 或含费口径不明：不比较有效率；
- 银行到账缺失：只分析到结算；
- 参考率时间不匹配：仅作背景；
- 费用无法解释：保留未解释差额；
- 用户要求实时汇率、交易或换汇建议：明确越界。

## 质量门

- 所有金额属于同一或明确拆分的交易链；
- 币对、方向、gross/net、费用和时间清楚；
- 四类汇率未混写；
- 可比性通过后才比较；
- 差额分解闭合或保留未解释项；
- 情景与预测明确分开；
- 未调用三个市场研究 MCP；
- 未交易、划款、监控或推荐具体时点。
